Glyph Effects change the **raster appearance** of a scene after geometry has
been projected and depth-tested. A parameter-only update reuses the retained
glyph frame, so it does not transform or rasterise every polygon again. Effects
remain inside the normal render transaction: they add no DOM nodes and every
affected `<pre>` is assigned at most once.

Install the optional catalog alongside the binding you use:

```bash
pnpm add @glyphcss/effects glyphcss
```

The catalog contains `matrixRain`, `flowText`, `scan`, `wipe`, `scramble`,
`glitch`, `noiseDissolve`, `ripple`, and `fieldSynth`.

## Composition and mapping

- `blend: "replace"` makes the effect the texture: zero emitted coverage hides
  that part of the surface. Matrix rain therefore describes the model with the
  falling strands alone.
- `blend: "over"` preserves the shaded glyph texture and paints only active
  effect cells over it.
- `target: "surfaces"` limits writes to visible rendered geometry.
- `target: "viewport"` can also author the base output's background.

`flowText` and `scan` default to `space: "auto"`: authored,
perspective-correct UVs win when available, followed by retained world positions
and geometric face normals. `matrixRain` defaults to `space: "object"` instead —
a volumetric mesh-local field is matrix rain's natural form (see
[`space: "object"`](#space-object--volumetric-mapping) below) — so a matrix-rain
preset tuned under the old `"auto"` default (its `scale` in particular means a
different thing under `"object"`) should set `space: "auto"` explicitly to keep
its old look. Choose `"surface"` to force the generated geometry
mapping even when UVs exist. For generated `down`, world `-Z` is projected into
each face's tangent plane: slopes follow their downhill gradient, coplanar
triangles agree, and differently oriented faces derive different directions.
When a face normal is parallel to world `-Z`, the projection has zero length, so
that plane receives a deterministic pseudo-random in-plane direction. `up`
reverses the generated flow; `left` and `right` use its perpendicular lane axis.
If surface fields are unavailable, the effect falls back to canonical projected
scene coordinates. Choose `"scene"` to force projected mapping.
The `scale` parameter controls pattern frequency without changing scene glyph
density. Text effects accept printable, single-cell sets such as `HOLA`,
`⣿⠿⠷`, `ᚠᚢᚦ`, or `←↑→↓`; combining marks, emoji, and double-width glyphs are
rejected because they would break the fixed cell grid.

Generated Matrix rain fits each quantized coplanar surface basis to projected
glyph-cell space, then evaluates its sparse mask and glyph lookup in the same
orthogonal face-local field. Glyph phase is periodic distance behind the same
moving head that defines the trail, so the word reads and travels at the strand's
direction and speed on walls, slopes, and foreshortened roofs.
Every active trail cell emits full coverage; `Streams` and `Trail` create the
sparse shape without coverage dithering breaking a word into isolated glyphs.

Matrix rain's `Color mode` can preserve the model's original colors or use a
single `Monochrome color`. In monochrome, each strand lights a bright head with
the `Original head color` and fades its tail toward black — the classic
head-to-tail falling-code gradient — while the retained surface shade still
modulates brightness, so lighting, shadows, texture luminance, and the 3D
silhouette remain visible.

### `space: "object"` — volumetric mapping

`"auto"`/`"surface"` give every polygon its own 2D parameterization (a cube's
caps use one axis pair, its walls another), so faces cannot agree on one flow
and a face turned edge-on to its own projection plane gets an exploding UV
gradient — visible as Matrix rain losing cohesion or smearing into fuzz as a
mesh rotates. `space: "object"` fixes this by stopping the pattern from being
painted per-face at all: it becomes a **field filling the mesh's volume**,
sampled at each covered cell's position in the mesh's own pre-transform 3D
frame. Faces become windows into the same body of rain, so they agree by
construction, and rotating the mesh turns the object through a field that
stays put relative to it — no seams, no per-face blend weights, no stretch.

Matrix rain has a natural 3D form and uses this **volumetric** formulation
directly — this is why `matrixRain` defaults its `space` param to `"object"`
(`flowText`/`scan` still default to `"auto"`, since their triplanar fallback
is a compromise, not a natural fit). The mesh-local frame is Z-up, matching
glyphcss's world convention, so a text mesh reads `X` = extrusion depth, `Y` =
width, `Z` = height. The
strand's phase therefore runs along `Z` for `down`/`up` and along `Y` for
`left`/`right`, and lanes are indexed by the two remaining axes — always
including depth (`X`), so cells at different depths in the same column share a
strand. A cap cell and an
adjacent wall cell read the same underlying `(x, y, z)` at their shared edge,
so the same strands continue across the seam instead of restarting.

Each cell's lane is a hashed integer bucket of its `objectPosition`
(`Math.floor`'d), so a mesh rotation that nudges a cell's sampled point across
a lane boundary swaps it to a whole new, unrelated strand. Because the
supersampled rasterizer picks that sampled point from the nearest covered
subcell to the cell's screen-space center, which subcell wins can itself flip
between adjacent frames even under a tiny rotation. To keep that from reading
as a strand popping in and out, matrix rain fades a cell's coverage out as its
sample nears a lane boundary (within 18% of the lane's width on either side)
instead of hard-committing right up to the edge — a crossing reads as a brief
fade, not a pop.

`scan` and `flow-text` are inherently 2D effects with no 3D form of their own
(a scan band, a line of reading text), so `space: "object"` gives them a
**triplanar** fallback instead: each covered cell projects onto whichever of
the three axis-aligned planes its face normal most faces (X-facing reads
`(y, z)`, Y-facing reads `(x, z)`, Z-facing reads `(x, y)`), blended by
`normalize(|normal|^4)`. The exponent (`4`) is the seam-vs-mush knob: `1`
blends across a wide band around each normal transition (visible double-vision
where two projections disagree), while a much higher exponent collapses
toward a hard per-axis seam; `4` is the conventional triplanar starting point
that keeps the blend narrow without a visible seam line.

`space: "object"` requires the retained `objectPosition` cell field, which
only exists in solid mode (hard surface requirements are solid-mode-only, same
as `worldPosition`/`normal`/`uv0`). In wireframe/voxel modes it degrades to
the same generated-surface/scene fallback `"surface"` already uses when its
own optional inputs are unavailable — never a silent empty render.

`scale` means something different under `"object"`: a 3D field frequency
rather than a 2D UV-domain frequency. A `scale` tuned for `"auto"`/`"surface"`
on a given mesh will not carry over 1:1 to `"object"` on the same mesh —
re-tune it after switching mapping.

## Field synth

`fieldSynth` is a small composable synth: up to six oscillators, each a
spatial **field** (`radial`, `linearX`, `linearY`, `diagonal`, `angular`,
`spiral`, `noise`) sampled through a **waveform** (`sin`, `triangle`, `saw`,
`square`), combined into one scalar and mapped to a glyph ramp and color. It
is the glyph-grid analogue of a fragment shader running over projected
surfaces — composing and interfering a handful of oscillators is where the
emergent moiré, plaid, sonar, and lattice patterns come from.

### Voices

Each of the six voices (`field1`/`wave1`/`freq1`/`speed1`/`amp1` through
`field6`/`wave6`/`freq6`/`speed6`/`amp6`) is independent:

- `fieldN` — the spatial field the oscillator samples. `radial` measures
  distance from the origin, `angular` measures the angle around it, `spiral`
  combines both, `linearX`/`linearY`/`diagonal` are axis-aligned ramps, and
  `noise` is a 3D value-noise field that evolves in place over `time` (rather
  than sliding across the surface the way the other fields do at nonzero
  `speedN`).
- `waveN` — the waveform applied to the sampled field value.
- `freqN` — spatial frequency, in cycles per unit.
- `speedN` — animation rate, in cycles per second (`time` drives phase).
- `ampN` — a **mix weight**, not a signal gain. The first active voice enters
  the combine chain at its weight; every later active voice then blends the
  running result toward `combine(result, voice)` by its own `ampN`. `ampN: 0`
  skips that voice entirely rather than forcing the combined result toward
  zero the way a `multiply` gain of `0` would, and a low `ampN` gently mixes
  a voice in instead of crushing the field.

### Combine, gain, bias

`combine` (`add` / `multiply` / `max` / `min` / `difference`) is the binary
operator active voices are folded through, pairwise, in voice order. `gain`
(contrast) and `bias` (brightness) then map the combined scalar to `0..1` for
output: `value = clamp01(bias + gain * combined * 0.5)`.

`combine: "argmax"` is the exception — it is **categorical**, not a fold. It
reports *which* voice won a cell rather than by how much, giving every cell in
a region one flat level (and, with `voiceColors`, the winning voice's own
colour) instead of a value that keeps varying inside it. That is what makes
hard-edged tilings reachable: three plane waves 60° apart under `argmax`
produce the rhombille/cube tessellation, which no value-folding operator can
express. Note `amp` stops being a mix weight there and becomes a comparison
weight — a quiet voice simply loses everywhere rather than blending in.

### Placement: scale and origin

`scale` sets pattern frequency without changing scene glyph density.
`originU`/`originV` place the center that `radial`, `angular`, and `spiral`
measure from.

Each voice can also carry its **own** placement, which the global values are
the baseline for:

- `angleN` (degrees, default `0`) rotates that voice's sampling frame about
  its own origin. This turns the three fixed linear fields into one steerable
  plane wave — the continuum between them is where fine moiré lives (two
  gratings a few degrees apart). It does nothing on `radial`, which is
  symmetric about its centre: `hypot(x - cx, y - cy)` is unchanged by
  rotation. `angular`, `spiral` and `noise` all respond.
- `originUN`/`originVN` (default `0`) offset that voice's centre from the
  global origin, in the same scaled domain units, so two `radial` voices can
  sit on **different** centres — the classic interference figure, which was
  unreachable at any voice count while the centre was shared. On generated surface coordinates (no usable authored UV),
origin resolves **per face**: `originU: 0.5, originV: 0.5` centers the
pattern on each visible face's own covered UV bounds rather than on one fixed
point in world space, so radial/spiral patterns stay centered as the camera
moves between faces.

### Output: ramp, color, lighting

- `glyphs` is a **ramp** indexed by the mapped `0..1` value (dark → dense),
  not a random-pick character set — see [`GlyphRamps`](#glyphramps) below, or
  author a string such as `" .:-=+*#%@"`. A leading space renders a
  genuinely blank cell, giving the ramp a true dark step.
- `subcellRes: "1x1" | "2x4" | "ink"` (default `"1x1"`) swaps the ramp-indexed glyph
  for a synthesized Braille pattern character at `"2x4"`: the combined field
  is resampled and thresholded at each of a cell's 8 dot positions and packed
  into one `U+2800`-block glyph — still exactly one glyph per cell, so it does
  not change the renderer's single-glyph-per-cell output contract. The 8
  offsets are exact under `space: "scene"` (the domain coordinate is affine in
  col/row there); under `"auto"`/`"surface"` they're reconstructed by
  finite-differencing neighboring cells' resolved coordinates, a local-affine
  approximation that shears on genuinely curved surfaces (a sphere, the round
  part of a cylinder, …) the same way the static field-synth exporter's own
  affine-fit optimization only applies to the flat case.
- `color` / `colorB` / `gradient` blend a single two-color gradient across
  the mapped value (`gradient: 0` is solid `color`, `1` is a full blend to
  `colorB`).
  At `"ink"` it stops shading by level and **contours** the field instead, the
  way `mode: "ink"` outlines geometry rather than filling it. `inkLevels`
  (`1..12`, default `4`) cuts the amplitude axis into that many evenly spaced
  levels (`n / (levels + 1)`, so neither extreme gets a degenerate line) and a
  cell inks where a level falls *between* it and a neighbour — a real crossing,
  which is what draws a continuous line rather than a scatter of near-level
  marks. The stroke is oriented perpendicular to the local gradient into the
  same four 45° buckets the geometry `ink` mode uses. Like that mode it draws
  only lines: plateaus and interiors stay empty, and a square wave's flat crest
  needs no special case because its step is an abrupt gradient the crossing test
  already sees. `"ink"` ignores the ramp (as `"2x4"` does) and emits plain-ASCII
  strokes, because box-drawing glyphs are missing from common monospace faces
  and would desync the character grid. A contour of an oscillating field is
  inherently dense — a `freq 6` voice crosses a level on most cells at 32×12 —
  so legibility comes from *fewer* `inkLevels`, not a higher one.
- `voiceColors` (boolean, default `false`) replaces that single gradient
  with a **per-voice** blend instead: each active voice's own `colorN` is
  mixed into the cell color weighted by that voice's contribution, so the
  output color composes through the mix rather than following one static
  gradient.
- `lit` (`0..1`, default `1`) modulates the resolved color by the surface's
  Lambert shade, so scene lighting reads through the texture; `lit: 0` is
  flat/unlit.

`fieldSynth` shares the same `space: "auto" | "surface" | "scene"` mapping
described [above](#composition-and-mapping).

### Example

```ts
import { createGlyphScene } from "glyphcss";
import { GlyphEffects } from "@glyphcss/effects";

const scene = createGlyphScene(host, { mode: "solid", autoSize: true });
const synth = scene.addEffectLayer({
  effect: GlyphEffects.fieldSynth,
  blend: "replace",
  params: {
    field1: "radial", wave1: "sin", freq1: 4, speed1: 0.6, amp1: 1,
    field2: "angular", wave2: "saw", freq2: 6, speed2: 0.3, amp2: 1,
    combine: "multiply",
    glyphs: " .:-=+*#%@",
    color: "#ffcf5a",
    colorB: "#ff4fa3",
    gradient: 0.6,
  },
});

function frame(now: number) {
  synth.params.time = now / 1000;
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

scene.addEffectLayer({

### Font-calibrated ramps

`GlyphRamps` above are authored guesses — hand-picked and eyeballed against
one font. Change family or weight and the gradient bands unevenly, because
the glyphs' actual ink coverage was never measured. `calibrateGlyphRamp`
measures it: it paints each candidate glyph onto a 2D canvas in a given font,
sums its alpha-weighted ink coverage, sorts by coverage, and collapses
glyphs that land in the same coverage bucket (two visually identical ramp
steps are a defect, not detail) into a ramp that's perceptually linear for
**that font**.

```ts
import { calibrateGlyphRamp } from "@glyphcss/effects";

const { ramp } = calibrateGlyphRamp({
  font: { family: "ui-monospace, Menlo, monospace", size: 32 },
  steps: 12,
});
// ramp is a plain string, e.g. " .'`,:;+=xXo#8@" (exact glyphs depend on
// the resolved font) — drop it in anywhere a ramp is used today.
```

`measureGlyphInkCoverage(glyph, { font })` is the underlying per-glyph
measurement, exported separately if you want raw coverage numbers instead of
a generated ramp.

Both are **browser-only** — the real measurement needs a Canvas 2D context
(`document.createElement("canvas")`). Off the DOM (SSR, a worker, a test),
pass `canvasFactory` to supply any Canvas-2D-compatible surface, such as
[`@napi-rs/canvas`](https://github.com/Brooooooklyn/canvas)'s `createCanvas`.

The result is a **plain string**, the same shape as `GlyphRamps` — it is
data, not a live measurement tied to `@glyphcss/effects`. That's what keeps
it free to use anywhere a ramp slots in, including static compile:
`compileScene` and the rest of the static-compile toolchain stay
byte-identical to the runtime render, because a calibrated ramp is no
different from an authored one once it's a string — for example, registered
as a solid-mode ramp on a `glyphcss` `WIREFRAME_PALETTES` entry:

```ts
import { compileScene, WIREFRAME_PALETTES } from "glyphcss";
import { calibrateGlyphRamp } from "@glyphcss/effects";

const { ramp } = calibrateGlyphRamp({ font: { family: "Menlo, monospace" }, steps: 12 });
WIREFRAME_PALETTES.myCalibrated = { ...WIREFRAME_PALETTES.default!, solid: ramp.split("") };

compileScene({ polygons, mode: "solid", glyphPalette: "myCalibrated" });
```

The gallery's Rendering dock exposes this as the **Calibrated** glyph
palette option, alongside the authored named palettes — pick it to see the
live scene switch from an authored ramp to one measured in the gallery's own
font.

## Use Anime.js directly

The layer handle deliberately exposes a stable flat parameter object. Anime.js
can target it without a GlyphCSS adapter:

```ts
import { animate } from "animejs";

animate(layer.params, {
  time: 60,
  duration: 60_000,
  loop: true,
  ease: "linear",
});
```

Anime owns time, easing, timelines, springs, and playback. GlyphCSS owns the
spatial program, retained frames, composition, and final write.

## Current boundary

The implemented runtime accepts `baseColor`, `baseShade`, `depth`, `normal`,
`worldPosition`, and `uv0` program inputs, plus the invariant base/input glyph
and coverage buffers. Hard surface requirements require solid mode;
`optionalRequirements` let a program request those retained fields while still
providing a wireframe/voxel fallback. It supports ordered `over`/`replace`
layers and scene-root `surfaces`/`viewport` targets. Mesh-handle targeting,
scene-image sampling/displacement, shader-like scratch graphs, surface-key and
UV-footprint fields, and static compile/export of effects still reject
explicitly. That broader graph and sampling architecture is planned future
work beyond this slice.
