# Glyph Effects and field-synth — design notes

> Design notes moved out of `AGENTS.md` (the agent guide keeps the contract and points here).
> Covers: `transformCells`, semantic cell frames and the control tensor, retained effect layers and per-object targeting, volumetric inputs (`objectExit`, `dynamicRequirements`), field-synth's volumetric branch, voice layers, carve/xray, the SDF voice family, the field program IR, sphere tracing, the authoring tier and program-as-data.

**Post-rasterize cell effects.** A scene's optional `transformCells` hook runs after rasterization and depth testing but before the final grid is stringified. It receives a `CellGrid` and may change cell characters or colors without adding DOM nodes or extra writes. In solid mode, requirement-gated optional buffers expose the final shaded scalar (`shade`), depth-winning world position (`worldPosition`), geometric face normal (`normal`), and authored perspective-correct UV (`surfaceUv`). Empty or unavailable vector/UV cells contain `NaN`. Under supersampling, world position, normal, and UV come from the same covered subcell nearest the output-cell center; shade is box-filtered with uncovered samples contributing zero. The hook remains inside the render pass: the transformed grid is still joined once and written to the `<pre>` exactly once. It receives a SECOND argument identifying which layer's grid it was handed — `GlyphTransformCellsLayer` (`{ detail: boolean; mesh?: string; density?: number; cellToSceneGrid: readonly [number, number, number, number, number, number] }`), so a hook can give ONE detail mesh its own treatment instead of guessing from grid dimensions; `mesh` is that mesh's transform `id` when the caller named one. `cellToSceneGrid` is the affine mapping THIS grid's own cell coordinates to the scene's BASE grid cell coordinates (`sceneCol = a*col + e`, `sceneRow = d*row + f`, encoded `[a, 0, 0, d, e, f]`; identity `[1, 0, 0, 1, 0, 0]` for the base grid itself) — the same quantity `GlyphEffectCoordinates.cellToSceneGrid` already carries for the generic effect compositor, exposed here too so a hook can convert a cell it was handed into base-grid coordinates without re-deriving the per-mesh detail-layer fit math; `@glyphcss/maps`'s `line`/`contour` stroke layers are the reference consumer — they stamp into every output grid a scene produces, each in its own coordinate frame, by projecting once in base-grid space and converting through this affine per grid. The parameter is optional and a hook must tolerate `undefined`: renders routed through the effects pipeline's own cell hook do not thread layer identity.

When semantic output is active, `scene.getGlyphSemanticCellFrame()` exposes an immutable, last-committed **base-grid** snapshot of depth-winning polygon → surface → instance → class lineage. It is derived from that same rasterized winner buffer, never from visible glyphs and never by a second projection; it is `null` in visible mode. Detail-layer cells are deliberately excluded because they have their own grids and no base-cell address. Control-frame capture also retains separately addressable `albedoRgb` (texture × authored base-color factor) and `targetRgb` (that albedo under the per-cell ambient/key Lambert and direct-only shadow policy) from the same winning subcell; these are not inferred from presentation spans.

The fixed model-control tensor is a 17-channel NCHW keyframe: visible glyph, semantic glyph/color, depth, normal, world position, surface UV, explicit surface-UV validity, coverage, and Lambert shade. Its temporal form prepends six warp/validity/disocclusion/confidence channels for a total width of 23. Raw control frames continue to preserve unavailable authored UVs as `NaN`; tensor UV value planes use zero only together with `surface-uv-valid = 0`, so a missing mapping never aliases a legitimate authored `(0, 0)` corner.

**Retained Glyph Effects.** `scene.addEffectLayer()` mounts ordered, scene-root appearance programs without adding output elements. The first geometry render retains an immutable `CellGrid` for the base `<pre>` and every detail `<pre>`; changing `layer.params`, opacity, blend, order, or enabled state then recomposes and safely encodes those retained grids without transforming or projecting the mesh again. The handle's flat `params` object has stable identity, validates known string keys, accepts Anime.js/private symbol metadata, and automatically schedules a coalesced effect transaction. Generic effects run before the legacy `transformCells` escape hatch. An effect-only transaction stages every affected string before assigning each `<pre>` at most once. With no mounted effect and no hook, the original direct renderer remains byte-identical and does not allocate retained effect frames.

The current generic compositor supports `over`/`replace`, `"surfaces"`/`"viewport"`/mesh-handle targets, canonical base-grid affines across detail densities, and the `baseColor`, `baseShade`, `depth`, `normal`, `worldPosition`, `objectPosition`, `objectExit`, and `uv0` requested inputs. Hard surface requirements are solid-mode-only; `optionalRequirements` retain those inputs in solid mode but allow a program-defined fallback in wireframe/voxel modes. Scene-image sampling, program scratch buffers, surface-key/UV-footprint inputs, and static compile/export evaluation of a mounted effect are not implemented yet and reject explicitly (field-synth's own static exporter is a separate, explicitly-scoped path — see "Compilation" below).

**Per-object effect targeting.** `target` on `addEffectLayer` accepts `"surfaces"` (default, scene-wide), `"viewport"`, a single `GlyphMeshHandle`, or a `readonly GlyphMeshHandle[]` — a layer applies only to the mesh(es) named. A handle/array target normalizes at mount to a canonical, immutable `Set` of mesh ids (module-level monotonic counter, never aliasing across scenes); `setOptions` with an equivalent set is a no-op, a genuinely different set throws (live retargeting is out of scope — remove and re-add the layer instead), and plain `"surfaces"`/`"viewport"` retargeting is unaffected and stays freely mutable. The mechanism is `targetCoverage`, not emission-zeroing: a targeted layer's per-cell `targetCoverage` is `0` on any cell whose depth-winning mesh is not in the target set, base coverage otherwise — zeroing the program's own output instead would ERASE the base on non-targeted cells under `blend: "replace"` at opacity 1, since `inputWeight` is itself derived from `targetCoverage`. The depth-winning mesh id is a solid-mode-only per-cell buffer (`CellGrid.winnerMesh`) retained alongside the existing shade/world-position/normal buffers; outside solid mode no winner data exists, so a mesh-targeted layer degrades to fully inactive (never a throw), and a removed/disposed mesh's id simply matches no cell, same degradation. It is never a `GlyphEffectRequirement` — a program cannot request it — but as of the Phase 2 P1 fix below it IS surfaced read-only on `GlyphEffectFrameView.winnerMesh` (populated whenever `objectExit` retention is active, which every carve layer already sets, or a layer is mesh-targeted): a volumetric subcell program needs exact mesh-identity equality between neighboring cells, which `objectPosition`/`normal` alone can't express for two coplanar, same-normal meshes. Occlusion-blanked cells (winner `-1`) are never in any target set. Each per-mesh detail layer (its own `<pre>`) carries its own real winner-mesh id, so targeting applies per output grid — a layer can target only a detail mesh, only the shared base grid's meshes, or both. A later scene-wide layer still composites OVER a targeted layer's output, including painting into carve holes — that is global ordering working as designed, not a bug. React/Vue `<GlyphEffectLayer target>` and `<glyph-effect-layer>` all forward `GlyphMeshHandle`/array targets; the React/Vue wrappers diff a mesh-array `target` prop by its canonical id set (not `Object.is`), so a fresh `[a, b]` array built every render is a no-op instead of a spurious `setOptions` call. `@glyphcss/effects` supplies Matrix rain, flow text, scan, wipe, scramble, glitch, noise dissolve, ripple, and **field synth** as reusable definitions. `field-synth` is a small composable synth — up to nine oscillators (`fieldN` × `waveN`: radial/linearX/linearY/diagonal/angular/spiral/noise/linearZ/gyroid/menger/sierpinski × sin/triangle/saw/square/step, each with `freqN`/`speedN`/`ampN`), combined (`add`/`multiply`/`max`/`min`/`difference`/`argmax`) into one scalar field mapped to a glyph ramp + color, over `space` — for emergent moiré/interference patterns. Every voice except `noise` and the SDF family (`gyroid`/`menger`/`sierpinski`, added in slice 2 — see below) is a 1D wave sampled along a scalar projection of the plane, so it is CONSTANT along its own level sets (parallel lines for linearX, circles for radial, rays for angular, spirals for spiral) and its terrain is ruled or revolved for those voices — genuine 2D relief from them only appears through `combine`. The SDF family breaks that invariant on its own: `gyroid`/`menger`/`sierpinski` are inherently volumetric implicit surfaces, not a 1D wave along any scalar projection, so a single SDF voice already carries genuine 2D/3D relief with no `combine` needed. Each voice additionally carries `angleN` (degrees; rotates that voice's sampling frame about its own origin, turning the three fixed linear fields into one steerable plane wave — radial is invariant to it) and `originUN`/`originVN` (an offset from the global origin in the same normalized domain units, so two radial voices can sit on DIFFERENT centres, which is the classic interference figure and was unreachable at any voice count while the centre was shared). `combine: "argmax"` is CATEGORICAL rather than value-folding: it reports WHICH voice won, giving each region one flat level (and, with `voiceColors`, the winning voice's own colour) instead of a value that keeps varying inside the region. That is what makes hard-edged tilings reachable — three plane waves 60° apart under argmax produce the rhombille/cube tessellation, which no value-combining op can express. `combineSynth` degrades argmax to `max` when called pairwise; the winning identity is resolved by `evaluateVoices`, which sees the whole stack at once and is the single evaluator the ramp, the 2x4 subcell probes and the ink gradient probes all share. `ampN` is a MIX WEIGHT (blends the result toward `combine(result, voiceN)` per voice, not a signal gain), so low amp gently mixes instead of `multiply` collapsing to flat; `amp 0` skips the voice. `lit` (0..1) modulates output color by the surface Lambert shade so lighting reads through the texture. `voiceColors` blends each active voice's `colorN` by its contribution (per-voice color composition); off keeps the `color`/`colorB`/`gradient` value-gradient. `subcellRes` selects how the scalar field becomes glyphs: `"1x1"` indexes the ramp by level (one glyph per cell), `"2x4"` thresholds eight subcells into a Braille dot mask, and `"ink"` CONTOURS the field instead of shading it — `inkLevels` cuts the amplitude axis into that many evenly spaced levels (`n / (levels + 1)`, so neither extreme gets a degenerate line) and a cell inks where any level falls BETWEEN it and a neighbour, which is what makes a continuous line rather than a scatter of near-level marks. The stroke is oriented perpendicular to the local gradient into the same four 45° buckets the geometry `ink` render mode uses. Like that mode it draws ONLY lines: plateaus and interiors stay empty, and a square wave's flat crest needs no special case because its step is an abrupt gradient the crossing test already sees. `"ink"` ignores the ramp (like `"2x4"`), gives inked cells full coverage rather than level-scaled coverage (half a contour lies below a level and would otherwise be nearly invisible), and emits plain-ASCII strokes because box-drawing glyphs are missing from common monospace faces and would desync the character grid. A contour of an oscillating field is inherently dense — a `freq 6` voice crosses a level on most cells at 32×12 — so legibility comes from fewer `inkLevels`, not from a higher one. `@glyphcss/effects` also exports `GlyphRamps` (named character-sets: Fade/Blocks/Shades/Dots/Binary/ASCII/Hatch/Stars/Digital). The **`/synth` website page** is the front-end: dual-sidebar modular synth — voice cards (add/remove, live per-voice previews that stay static until hovered, a color swatch, icon multi-toggles, per-voice mix) grouped into collapsible per-layer `LayerGroup`s (blend mode, mix, threshold, invert) in the voice sidebar; Stage/Mix/Output/Lighting Dock; a `Mapping` dropdown is the SOLE 2D/3D control (`space` itself — the earlier separate 2D/3D toggle was removed as a duplicate) and, once a volumetric stage is active, an optional camera auto-orbit is available; a live preset gallery including a `pyramid` stage and three volumetric presets (Sierpinski pyramid, Breathing gyroid, Menger (cssGraphics)) — full patch persisted to the URL through a two-tier repair gate: an ordered predicate → reset-keys table repairs known-invalid combinations (e.g. a stale `carve` + `subcellRes: "2x4"` URL), falling back to a full effect-param reset (preserving valid non-effect state like shape/camera/lighting) when a validator has no matching table row, so a crafted or legacy URL always hydrates to a working page instead of throwing. For surfaces it gives each face a local 0..1 UV so patterns map per-face. For flow-text/scan, `space: "auto"` (their default) resolves authored UVs first and then generated world-surface coordinates; `space: "surface"` forces the generated orientation-aware mapping, while `space: "scene"` uses projected scene coordinates. `space: "object"` stops painting the pattern per-face and instead treats it as a field filling the mesh's own pre-transform 3D volume, sampled from the retained `objectPosition` cell field (interleaved x/y/z, requirement-gated exactly like `worldPosition`/`normal` — allocated only when a mounted effect's `requirements`/`optionalRequirements` asks for it). `objectPosition` is recovered by carrying each polygon's PRE-transform vertices alongside its baked world vertices (`Polygon.objectVertices`, set by `applyTransform` in `createGlyphScene.ts`) and barycentric-interpolating those with the SAME weights used for `worldPosition` — cheaper and exact under non-uniform scale, unlike inverting a per-mesh matrix. Matrix rain has a natural 3D form and uses this volumetric formulation directly (lanes indexed by the two mesh-local axes perpendicular to `direction`, phase along the third), so a cap cell and an adjacent wall cell read the same underlying `(x, y, z)` at their shared edge and the same strands continue across the seam — this is why matrix rain (unlike flow-text/scan) defaults to `space: "object"` rather than `"auto"`. `scan`/`flow-text` have no 3D form of their own, so `space: "object"` gives them a triplanar fallback instead: each cell projects onto whichever of the three axis-aligned planes its face normal most faces, blended by `normalize(|normal|^4)` (`4` is the seam-vs-mush knob — the conventional triplanar starting point). `objectPosition` only exists in solid mode (hard surface requirements are solid-mode-only); `space: "object"` degrades to the same generated-surface/scene fallback `"surface"` already uses in wireframe/voxel modes, never a silent empty render. `scale` means a 3D field frequency under `"object"`, not a 2D UV-domain frequency — a value tuned for `"auto"`/`"surface"` does not carry over 1:1, which is why a saved matrix-rain preset that tuned `scale` under the old `"auto"` default should pin `space: "auto"` explicitly if it needs to keep its old look. Matrix rain's volumetric lane assignment (`objectVolumetricAlongLane`) hashes each cell's `objectPosition` into an integer lane per `Math.floor` bucket; because the supersampled solid rasterizer picks that position from the nearest COVERED subcell to a cell's screen-space center (see "Per-mesh detail layers" above), which subcell wins can flip to a different point — sometimes a different face — as a mesh rotates, even one frame to the next with the effect clock paused. A hard bucket boundary would turn that small sample jump into a swap to an unrelated `hash2` bucket (a strand popping in/out); `objectVolumetricAlongLane` instead fades a cell's coverage out (`edgeFade`, `OBJECT_LANE_EDGE_MARGIN = 0.18` of a lane's width on either side of its boundary) as the sample nears a lane boundary, so a boundary crossing reads as a graceful fade rather than a pop. `@glyphcss/fonts` authors UVs on every emitted polygon unconditionally, not only when a face carries a texture — front/back caps get a planar mapping normalized to the whole word's type-plane bounds (the glyph's own 2D authoring space, computed before any mesh `rotation` is applied), and side walls get a strip mapping (`u` = fractional arc-length position around the glyph contour, `v` = fractional extrusion depth). Because those UVs are fixed in mesh-local space, `space: "auto"` resolves the authored-UV path for text by default, so Matrix/flow/scan patterns stay locked to and turn with the letterform surface instead of the generated world-surface fallback, which is anchored to world space and would otherwise slide underneath a rotating mesh. On generated surface coordinates, `down` is world `-Z` projected into each geometric face's tangent plane; coplanar polygons agree, differently oriented polygons derive different downhill directions, and a plane perpendicular to that vector gets a deterministic pseudo-random in-plane fallback. That `down` (vertical) axis is quadratic in the face normal, so it is already invariant to the normal's dominant-axis sign canonicalization; the derived `right` (horizontal) axis is `down × normal` — linear in the normal — and is explicitly counter-signed against that same canonicalization so it shares the same invariance, instead of flipping independently every time a rotating mesh's normal crosses the canonicalization boundary. This keeps a spinning mesh's generated-surface flow direction (matrix rain, flow-text, scan) continuous through a rotation: `right`/`left` no longer reverses out of step with `down`/`up` mid-spin. The only remaining discontinuity is the documented pseudo-random fallback itself, which fires only at the exact instant a face passes through perpendicular to `-Z` (no direction is more "down" than another there) — a single, expected re-pick, not a run of spurious flips. Generated Matrix rain fits each quantized coplanar surface basis to projected glyph-cell space, orthogonalizes its visible flow and lane vectors, and evaluates both sparse trail membership and glyph phase in that same face-local field. The word therefore shares the strand's direction and projected-cell velocity on sheared or foreshortened faces, remains ordered when a periodic strand wraps, and does not mutate in place while its mask moves separately. Active rain cells have full logical coverage; sparsity comes from lane selection and trail length, not fractional tail coverage that the compositor would dither into broken strands. Matrix also supports original surface colors or a configurable monochrome color; in monochrome each strand lights a bright `headColor` head and fades its tail toward black (still modulated by surface shade) for the classic head-to-tail falling-code gradient. The package owns no clock. Applications animate explicit parameters such as `time` directly or through Anime.js. React and Vue mirror the scene-root `<GlyphEffectLayer>` wrapper, and custom HTML configures `<glyph-effect-layer>` through JavaScript properties/`configure()` because executable definitions are values, not JSON attributes. `ANIMATIONS.md` records both this implemented slice and the richer approved graph/sampling architecture that remains.

**Volumetric effect inputs (`objectExit`) and `dynamicRequirements`.** `objectExit` (requirement) is the interleaved x/y/z **object-space exit point** of the view ray through the depth-winning mesh — the farthest intersection of that same mesh along the cell's ray, in the mesh's pre-transform coordinates, same NaN-for-unavailable contract as `worldPosition`/`objectPosition`. There is no separate ray buffer: an effect derives one as `normalize(objectExit − objectPosition)`, both endpoints barycentrically interpolated from `Polygon.objectVertices` (the same no-matrix-inverse discipline `objectPosition` established), so a grazing-silhouette cell where entry and exit coincide yields a degenerate ray an effect must treat as "no volume." Producing it needs a **second sweep**: the per-cell solid-pass winner is only final after the last polygon and back faces are culled before scan-fill, so a farthest-of-winning-mesh value can't come from the main pass. The sweep runs a farthest-depth rasterizer (mirroring `fillDepthTri`'s nearest-depth one, clipping near-plane-straddling triangles rather than skipping them — a perspective camera near or inside the mesh is the marquee case) restricted per cell to whichever mesh actually won there, via a polygon→mesh winner buffer (`winnerMeshBuf`) retained in visible mode specifically for this — distinct from the semantic-output-only, polygon-indexed `winnerPolygonBuf`. It runs once per output that retains effect inputs (the base `<pre>` and each per-mesh detail `<pre>`) at that pass's own supersample resolution, downsampled by the same nearest-covered-subcell selection `worldPosition`/`normal` use. **Convex-exact, concave-approximate**: for a convex mesh entry→exit is the exact solid chord; a concave mesh's segment may bridge void gaps (a documented approximation — the fix needs per-cell hit lists / depth peeling, future work). **Carved holes show the page background, never farther scene geometry** — anything behind the host mesh already lost the per-cell depth test before effects run, including cross-`<pre>`: a hole in a detail layer does not reveal base-grid geometry sitting behind it, because the occlusion id-map already blanked those base cells at rasterize time.

Because a static per-program `requirements` array would make every mounted patch — including plain 2D ones — pay for the second sweep, the generic effect protocol (`GlyphEffectDefinition`/`GlyphEffectProgram`, packages/glyphcss/src/api/effects.ts) gains an optional `dynamicRequirements(params): readonly GlyphEffectRequirement[]` hook, merged with the static `requirements`/`optionalRequirements` arrays and re-evaluated whenever a coalesced params transaction changes the hook's own result (a requirement-set change additionally invalidates retained inputs, not just recomposes). `dynamicRequirements` is optional-shaped like `optionalRequirements` — it degrades in wireframe/voxel modes rather than throwing, since the hook can't see the render mode. A requirement it returns that isn't in `SUPPORTED_REQUIREMENTS` still throws at mount, same as a static one. A dynamic input the *current live params* don't ask for reads as `undefined` on the frame view rather than erroring — worth stating explicitly (a Phase-1 reviewer note): a program must guard a dynamic buffer's presence itself, the same discipline `optionalRequirements` fallbacks already need. Field-synth's own hook returns `"objectPosition"` when `params.space === "object"`, adds `"objectExit"` when `params.render` is `"carve"` OR `"xray"`, and — separately — adds BOTH `"objectExit"` and `"objectNormal"` unconditionally whenever `params.colorStackOn` is set, regardless of `space`/`render`: the hook only ever sees flat `params`, never an opaque `colorProgram` (a colour voice using a normal-derived field could be hiding inside one), so it can't know in advance whether the colour stack will actually use a normal-derived field, and over-requesting is cheap — the normal-derived fields themselves still degrade to 0 outside `space: "object"`/solid mode. A plain 2D or non-carve/non-xray volumetric patch only avoids the exit sweep while its colour stack is also off.

**Field-synth's volumetric branch.** Under `space: "object"` with `objectPosition` retained, `fieldSynth` (unlike `matrixRain`/`scan`/`flowText` above) takes its own distinct branch: `(x, y, z) = objectPosition · scale` (matrix rain's precedent — `scale` is a 3D field frequency under `"object"`, not the 2D UV frequency `"auto"`/`"surface"` use). The 2D branch is separate code, not `z = 0` through one shared formula: `linearZ` (new field, appended to `SYNTH_FIELDS`) exists only in 3D; `diagonal` is `(x+y+z)/√3` in the volumetric branch vs. the untouched `(x+y)/√2` in 2D (changing the 2D constant would break existing presets like Zebra/Lattice); `noise` becomes a 4D hash (`synthNoise4(x·freq, y·freq, z·freq, time·speed)` — the 2D path's third `synthNoise3` axis is already time, so volumetric noise needs a fourth axis or it freezes); `angular`/`spiral` stay evaluated in the XY plane with `z` ignored (documented scope limit); `radial` is spherical distance from the voice origin. Voice origins gain `originW1..9` (default 0, 3D-only); `angleN` keeps its 2D meaning (rotation about Z). Every voice also gains `duty1..9` (default 0.5, the square wave's high fraction; other wave kinds ignore it) and `phase1..9` (default 0 cycles, added to every wave/field kind's argument) — `phase` exists because linear fields ignore the voice origin entirely (only `angle ≠ 0` and the radial/angular/spiral centers read it), so a middle-third selector needs `wave: square, duty: 1/3, phase: -1/3` rather than an origin shift. `subcellRes: "2x4"`/`"ink"` finite-difference the volumetric coordinate the same local-affine way the 2D generated-surface path already does; under `render: "carve"` both are legal (only `render: "xray"` still rejects them) — see "Carve mode" and "Volumetric subcell modes" below.

**Voice layers.** `layer1..9` (default 1, integer 1..3) opts a voice into one of three groups, each with its own `layerCombineL` (intra-layer fold, default = the patch-level `combine`), `layerThresholdOnL`/`layerThresholdL` (default off / 0, range −3..3 — an add-fold of three amp-1 voices spans ±3), `layerInvertL` (default off), and `layerBlendL` (`add`/`multiply`/`max`/`min`/`difference`, default `multiply`) + `layerAmpL` (0..1 mix weight, default 1) for how the layer's shaped output enters the cross-layer fold. Layers exist because no flat combine of separable (per-axis-projected) voices can express a per-scale membership rule like Menger's ("hole ⇔ at least two axes are in their middle third at that same scale") — the fix is a threshold *per scale* before scales combine, i.e. a layer with its own shaping stage; Cantor-dust-style per-axis rules remain reachable in the flat fold once voices are 3D and `duty` exists. A thresholded layer's folded value maps to **±1, not {0, 1}** — the downstream `clamp01(bias + gain·v·0.5)` mapping (default bias 0.5) is calibrated for a ±1 signal, and a {0, 1} indicator can never reach the ramp's empty end. An empty layer (no active voices) is skipped in the cross-layer fold exactly like an amp-0 voice is skipped in the intra-layer fold — otherwise it folds to 0 and the default multiply-blend annihilates the stack. **Backward compatibility is structural**: every voice on layer 1 with threshold/invert off and amp 1 is a single-layer stack whose output is exactly the pre-layers flat fold, so existing patches/presets/URLs are unchanged without migration. `combine: "argmax"` stays categorical and single-layer only — `validateParams` rejects a patch where argmax is the **effective** combine (its layer override, else the patch-level default) of any *populated* layer in a multi-layer stack; a multi-layer patch whose every populated layer overrides to a value op is valid regardless of the patch-level `combine`, which is then dead metadata by design. `voiceColors` still blends across all active voices regardless of layer — layers have no color model of their own.

**Carve mode.** `render: "paint" | "carve" | "xray"` (default `"paint"`) is field-synth's raymarched hollow-interior mode. Carve requires the volumetric branch (`space: "object"`, `objectPosition` + `objectExit` retained); in wireframe/voxel modes it degrades to paint like every other optional-requirement fallback. `subcellRes: "2x4"`/`"ink"` are legal under carve — see "Volumetric subcell modes" below — only xray still rejects them (`"xray-subcell-unsupported"`); the plain `"1x1"` path described here is carve's shading-only mode. Per covered cell it calls the public `marchGlyphField` (see below) over `objectPosition → objectExit` with the compiled field program as sampler. `marchSteps` (default 48, max 256) is a *minimum*, raised per cell to `ceil(2·chordLength·f_finest)` (the Nyquist floor below which thin walls render as shimmering false holes) — a measured 120×48-grid, depth-2-Menger, half-covered scene stays around 3ms/`evaluate()` call at the default (`bench/carve-march.md`). `f_finest` is duty-aware and the depth-3 recipe ships as a preset — see "Authoring tier" below for both. A sample counts solid when the same `clamp01(bias + gain·v·0.5)` mapping the ramp uses is `> 0` — no separate iso parameter. **Emission is at the raw guaranteed-solid march sample, not an interpolated hit position**: the marcher's secant refinement is exact for an affine field, but every voice/layer boundary in a hard-thresholded field (a square wave, any layer threshold) has a plateau at 0 under that same clamp mapping, so an interpolated position can land on the plateau's edge and resample non-solid. `FieldMarchHit.sampleX/Y/Z`/`sampleDistance` are the raw sample that actually triggered the hit and are guaranteed to resample `> 0`; carve emits at that point (the paint pipeline's ramp glyph, `lit`/shade, `voiceColors`, gradient) and multiplies color by `exp(−marchFade · sampleDistance)` — `sampleDistance`, not the chord-normalized `t`, so two cells with different chord lengths shade an interior wall identically instead of painting a spurious silhouette-tracking gradient. At `sampleDistance = 0` (surface-solid cell) the factor is exactly 1, so an everywhere-solid carve is byte-identical to paint on the same scene. A cell with no solid sample along the chord emits nothing — ordinary compositor semantics: `blend: "replace"` at opacity 1 composes holes to page background (the intended look, and what carve should be mounted with); `over` lets the base surface show through holes; `replace` at opacity < 1 Bayer-dithers the base back into them.

**Xray mode.** `render: "xray"` (appended to the render enum, slice 2) is field-synth's transmittance mode: the same volumetric branch as carve, but instead of a first-hit march it integrates density along the whole chord and reports how much of it a viewer sees through, rather than where it first stops. Per covered cell, density per sample is the same `clamp01(bias + gain·v·0.5)` mapping paint/carve use; transmittance `T = exp(−xrayGain · ∫ d dt)` (the integral in absolute domain units, via the public integrator below); brightness `B = 1 − T`. `xrayGain` is its OWN param (appended, default 4, min 0, max 16) — not `marchFade`: at `marchFade`'s default 1 a fully solid unit chord only reaches B ≈ 0.63 and typical preset domains never saturate, and `0` means opposite things in the two modes (no fade in carve, invisible in xray). **Coverage is forced to 1** for any cell with `B ≥ 1/255` regardless of the resolved color's alpha (the `subcellRes: "ink"` full-coverage precedent — fractional coverage would dither the transmittance look into noise); a cell under that threshold emits nothing. `lit` still modulates by surface shade; `voiceColors` is inert (and hidden in the UI) since a transmittance integral has no per-voice winner. A degenerate chord (no finite exit, zero length) emits nothing — deliberately different from carve's paint-at-entry fallback, since a full-strength rim ring around a transmittance volume would contradict the mode. **Uniform step count per `evaluate()` pass**: carve tolerates a per-cell step-count `ceil` flip (a sub-step shift in where the hit lands), but an integral does not — a ±1-2 step difference between neighboring cells can read up to ~20% apart in brightness, visible as per-cell speckle. Xray therefore computes ONE step count for the whole pass, from the MAX chord over every covered cell, and integrates every cell at that count; carve keeps its own per-cell count, unchanged. **A zero-mean oscillating field reads as fog under xray** — it integrates to roughly `bias` per unit length, so structure only shows once a voice is shaped near-binary first (the `Breathing gyroid` preset thresholds its layer for exactly this reason); a MIP/max-density accumulation mode is a recorded future option, out of scope for this slice. Validation mirrors carve's `space: "object"` requirement (same rejected-value error codes), but stays `subcellRes: "1x1"` only — unlike carve, which also accepts `"2x4"`/`"ink"` (see "Volumetric subcell modes" below) — since an accumulated transmittance integral has no per-cell hit point for either neighbor probe to read; xray degrades to paint in wireframe/voxel exactly like carve; `dynamicRequirements` returns `objectExit` whenever `render` is `carve` OR `xray`, and also whenever `colorStackOn` is set regardless of `render` (see above), so a plain paint patch only avoids the exit sweep while its colour stack is also off.

**SDF voice family.** `gyroid`, `menger`, `sierpinski` (appended to `SYNTH_FIELDS` after `linearZ`, slice 2) take a dedicated branch in `sampleFieldVoice`, like `noise` — and, unlike every other field, they read the voice **origin** (`originU/V/W`) as a pre-evaluation TRANSLATION of the sampled point, the opposite of every linear field's convention (which ignores origin entirely) and of radial/angular/spiral (which read origin only as a distance-from-center anchor): without translating the sample itself an SDF voice has no way to align to its host mesh, and `phase` is not a substitute — `phase` for an SDF voice is instead an ISO-LEVEL offset that erodes or dilates the solid, never a translation. `freq` is the lattice scale, applied ONCE to the translated sample; the shipped wave projection `t = raw·freq − time·speed + phase` every other field uses is NOT reused here (freq would apply a second time, doubling shell density to freq²) — SDF voices route through their own `t = raw − time·speed + phase`. `gyroid` is a 2π-normalized smooth implicit (`sin(2πx)cos(2πy) + sin(2πy)cos(2πz) + sin(2πz)cos(2πx)`, so `freq` means cycles-per-domain-unit like every other voice) used directly as the wave argument — its sign means "which labyrinth half," not inside/outside solid. `menger`/`sierpinski` are the signed distance to the **depth-`iter` box/tetra union** — an EXACT union distance via a pruned recursive descent of the same kept-child tree the digit-rule membership test walks (menger: 20-of-27 axis-aligned kept subcubes per level; sierpinski: 4-of-8 kept octants per level, the corner-tetra rule), not a Lipschitz-bound distance estimator: a true limit-set SDF is positive almost everywhere (the limit set has measure zero) and would carve to nothing. A parent box's own SDF is a valid lower bound for every descendant's, so the descent prunes any child whose bounding-box distance already exceeds the best union distance found so far. The cell convention is the unit cube `[0,1]³`, matching the recipe presets and the `pyramid` stage's own authoring window; the 2D branch evaluates at `z = 0` (a documented slice). `iter1..9` (integer 1..4, default 3, menger/sierpinski only, knob hidden otherwise) is capped at 4 because carve/xray's march resolution caps at 256 steps: menger `iter` 4 needs ~162 steps on a unit chord and fits, `iter` 5 needs ~486 and would render guaranteed false holes. The shared Nyquist step floor (below) reads each voice's own **effective finest frequency**, not the raw `freq`: `freq·3^iter` for menger, `freq·2^iter` for sierpinski, `freq·2` for gyroid, `freq` for everything else — a menger/sierpinski voice at `iter ≥ 3` is therefore expensive to march/integrate at full resolution (recorded reviewer P2); turn on `interactiveDownscale` while dragging camera controls on an `iter ≥ 3` menger/sierpinski patch. `step` (appended to `SYNTH_WAVES`) is a non-periodic waveform — `+1` when its argument is `≥ 0`, else `−1` (duty ignored, no cycle to shape) — legal on every field (a `linearX` + `step` voice is a half-space), and every SDF preset depends on this exact line: inside the solid `sdf < 0` → `raw > 0` → `t > 0` → `step = +1` → density `> 0.5` at the default bias → solid. The static exporter ports all three SDF fields and `step` through its own IR runtime with real-renderer parity — they export in the 2D branch like any other field/wave.

**The field program IR.** The internal evaluation form — an array of layers, each an array of voice records, plus per-layer combine/threshold/invert/blend/amp, no fixed length anywhere — is public as the field program IR, the seam a future field-authoritative primitive or spectral-analysis mode plugs into without touching the schema. `@glyphcss/effects` exports the types (`GlyphFieldProgram`, `GlyphFieldLayer`, `GlyphFieldVoice`, `GlyphFieldSampler`, `GlyphFieldEvalResult`, `GlyphFieldMarchOptions`, `GlyphFieldMarchHit`, `GlyphFieldMarchMiss`, `GlyphFieldMarchResult`), the evaluator `evaluateGlyphFieldProgram(program, x, y, z, time)`, and the sampler-agnostic marcher `marchGlyphField(entry, exit, sampler, opts)` where `sampler` is any `(x, y, z, t) => number` — carve calls it with the field-program sampler, but the marcher itself knows nothing about voices. `marchGlyphField` returns a first hit and cannot express an accumulated quantity; its sibling **`integrateGlyphField(entry, exit, sampler, opts) → { sum, steps, chordLength }`** (slice 2) is equally sampler-agnostic and drives xray's transmittance integral. Both share one exported step-count floor, **`glyphFieldStepCount(chordLength, opts)`** — `max(minSteps, min(cap, ceil(2·chordLength·finestFreq)))` — so carve and xray can never disagree about how finely a chord is resolved; `integrateGlyphField`'s quadrature is midpoint, not endpoint: `steps` samples at `t_i = (i + ½)/steps · chordLength`, weighted by `Δt = chordLength/steps`, with a non-finite sample contributing 0 — no endpoint double-counting. Field-synth's own params→IR compile (`stock.ts`) is one caller among others a hand-built program could replace.

**Preset named exports.** Alongside `GlyphFieldSynthEffect.presets`, four presets are individually exported by object identity for a consumer that needs to key off a SPECIFIC preset rather than a name string: `GlyphCubeTilesPreset`, `GlyphSierpinskiPyramidPreset`, `GlyphBreathingGyroidPreset`, `GlyphCssGraphicsMengerPreset` — the `/synth` page's per-preset stage-hint table (below) is the reference consumer, keyed by object identity so renaming a preset's display name can't silently drop its hint. (A later preset cull removed five other identity-exported presets — `GlyphMengerSpongePreset`, `GlyphGyroidXrayPreset`, `GlyphMengerSdfPreset`, `GlyphSierpinskiSdfPreset`, `GlyphMengerFlowPreset` — along with three more that were never identity-exported — "SDF bloom", "Iridescent sponge", "Iridescent shell"; `GlyphBreathingGyroidPreset`/`GlyphCssGraphicsMengerPreset` now inline the recipes those removed presets used to spread from, byte-identical to before.)

**`GLYPH_FIELD_SYNTH_VALIDATION_RULES`.** Every `validateParams` throw site in field-synth tags its thrown error with a stable rule id from this exported array (typed `GlyphFieldSynthValidationRuleId`; the error itself is typed `GlyphFieldSynthValidationError` with a `.code` field): `"empty-glyphs"`, `"non-positive-scale"`, `"multi-layer-argmax"`, `"carve-requires-object-space"` (covers both `render: "carve"` and `render: "xray"`), `"xray-subcell-unsupported"` (xray-only — see "Volumetric subcell modes" below for why carve no longer shares this rejection). This replaces a hand-maintained mirror list that could silently drift out of sync: a consumer (the `/synth` URL repair table) asserts every exported id is covered by its own repair rows, so a validator added here without a matching repair-table entry fails a real cross-package test instead of rotting quietly.

**Volumetric subcell modes (carve only).** `render: "carve"` + `subcellRes: "ink"` or `"2x4"` are legal (xray still rejects both, tagged `"xray-subcell-unsupported"` — an accumulated transmittance integral has no per-cell hit point for either neighbor probe to read).

*Ink-over-carve* contours the march's hit/hole boundary instead of shading every hit cell (outline sponges). The carve evaluate pass allocates per-evaluate local buffers — `hitState` (OUT / HOLE / HIT; OUT collapses "no geometry" and "geometry from a mesh outside this layer's target set", since both discard identically — the compositor's own `targetCoverage` weighting already discards whatever an OUT cell emits, regardless of which sub-case it is), `hitDistance` (the hit's `sampleDistance`, absolute domain units from the TRUE entry — its known consequence is a contour break across an entry-surface crease, accepted), and the hit's resolved color — fills them in the march loop, then a second pass resolves ink from those buffers alone (no re-march). New param `inkSpacing` (domain units, default 0.25, min 0.05, max 4, appended after every existing key) is an ABSOLUTE contour spacing, not a fraction of the observed depth range (that would make contours crawl frame-to-frame under orbit and degenerate on a flat wall); `inkLevels` is a documented no-op under carve-ink (2D `subcellRes: "ink"` keeps it). Inking rules: (a) `hitState` differs between any of a cell's 4 neighbors, OR two same-state HIT neighbors carry a DIFFERENT winner mesh id (`GlyphEffectFrameView.winnerMesh`, both ids known — Phase 2 P1 fix: `hitState` alone can't tell two coplanar, same-normal, globally-targeted meshes apart, so a contour previously bridged straight across that seam instead of rimming it) → rim, always inked, on BOTH sides of the boundary (a hole/OUT cell touching a hit is rimmed too, so it can borrow a color); (b)/(c) for a cell whose every neighbor shares both its state AND its winner mesh, a multiple of `inkSpacing` between two hit depths (contour) or too great a depth jump (interior edge) — contours never cross a hit/non-hit OR winner-mesh boundary, since both are already rule (a). Orientation: rim cells use the screen-space gradient of a mask that reads 0 for a non-HIT neighbor OR a HIT neighbor on a different winner mesh (a depth gradient is undefined against either — the naive fallback renders every rim cell as `-`); contour/edge cells use the depth gradient (both neighbors are real hits on the SAME mesh there). Both quantize through the same exported 4-bucket `inkGlyphForField` the 2D ink path uses. Non-inked cells emit nothing; inked cells get full (non-level-scaled) coverage; color is the cell's own hit color, or — for a rim cell with no hit of its own — its nearest inked hit neighbor's color, else the layer's base color.

*Braille-over-carve* (`subcellRes: "2x4"`) marches 8 sub-rays per covered cell, one per Braille dot position, sharing ONE step count sized from the longest of the 8 (+ the cell's own) chords (xray's own "uniform step count" rationale, applied per-cell). Sub-ray entry/exit endpoints interpolate the cell's own chord with its neighbors' via the same edge-mirrored gradient probe style the file already uses elsewhere, gated by STRICT neighbor eligibility: a neighbor participates only if its own entry AND exit are finite, it is in-target, it carries the SAME winner mesh id as this cell (`GlyphEffectFrameView.winnerMesh`, both ids known — Phase 2 P1 fix: an agreeing normal alone previously let a same-normal neighbor on a genuinely DIFFERENT mesh through, interpolating a dot's endpoint off the near mesh's own surface toward the far mesh's unrelated position), AND its geometric face normal agrees with this cell's (dot > 0.9, which independently catches the crease-edge case — two faces of the SAME mesh with disagreeing normals) — an ineligible axis's gradient defaults to 0, collapsing that axis's sub-rays to the cell's own center chord. One color per cell: the center sub-ray's hit color if it hit, else the first hitting sub-ray's (dot-scan order), else no emission.

**Sphere tracing for carve (qualifying SDF programs only).** `buildGlyphFieldDistanceOracle(program, { bias, gain }, time)` builds a per-voice signed-distance oracle — `D(p) = max_i D_i(p)`, `D_i(p) = (sdf_i(freq_i·R_i(p − o_i)) − c_i) / freq_i` (÷`freq_i` converts the freq-scaled SDF back to domain-unit distance; measured 2.9× overshoot at freq 3 without it) — or returns `null` when the compiled program doesn't qualify; carve marches with `marchGlyphFieldSphere` (the fixed marcher's public sibling) instead of the fixed grid whenever the oracle is non-null, and stays byte-identical to before when it's `null`. Qualifying is conservative, every condition normative: exactly one populated layer, `combine: "min"` (an intersection of ±1 solids — distance to it is the MAX of member distances, not `min`: an executed counter-case shows min-of-distances terminating inside the union where the solid test says empty), `thresholdOn` off, every active voice `menger`/`sierpinski` with `wave: "step"` and `amp === 1` (`gyroid` excluded — its implicit is not a genuine distance), `invert` allowed (negates the whole fold symmetrically, still distance-true), and `bias`/`gain` in the step-selective regime `bias + gain/2 > 0 && bias − gain/2 ≤ 0` (outside it the ±1 field is all-solid or all-empty, so the tracer's target iso isn't the one the solid test reads). The marcher steps by `SPHERE_MARCH_SAFETY · D` (0.9) and, on a sign change, overshoots `SPHERE_MARCH_OVERSHOOT_EPSILON` further into the solid and confirms with the REAL sampler before emitting — `marchField`'s own raw-sample plateau discipline, so a hit never lands on a hard-thresholded field's own zero plateau. **Stall/step-cap-pressure fallback** (amended after measurement): naive distance-stepping alone stalls approaching an off-ray feature on dense recursive fractals — measured 17% of fixed-step's hits lost to cap exhaustion at iter 3. `SPHERE_MARCH_STALL_STEPS` (8) consecutive advances below `SPHERE_MARCH_STALL_ADVANCE`, or the last step of the `SPHERE_MARCH_MAX_STEPS` (64) budget, falls back to a fixed-step scan of the remaining segment — but on the SAME absolute grid a plain fixed-step call over the FULL original chord would use (`fieldStepCount` applied to the full chord length, at the caller's own `steps`/`maxSteps`/`finestFreq`), not a freshly-derived grid for the shorter remaining segment: re-deriving the step count for a shorter segment shifts the Nyquist phase and can legitimately skip a thin feature the full-chord grid's own sample offsets would have caught, so "same per-cell step density" has to mean the same grid phase, not just the same step count, for the hit-set superset guarantee to hold by construction (measured at the time, against two now-removed presets — "Menger SDF"/"Sierpinski SDF", see below — 218/218 and 153/153 fixed-step hits recovered, vs. 182/218 and 127/153 pre-fallback). The equivalence bar: (a) sphere hit set ⊇ fixed-step hit set (restored by the fallback, strict); (b) identical ramp glyph on every shared hit, fallback-produced included — the invariant that actually holds everywhere; (c) sphere's hit distance ≤ fixed-step's and within one fixed step, but ONLY for PURE distance-stepping hits — a fallback hit is a separate `marchField` call over its own independently-quantized remaining sub-segment with no such guarantee relative to the full-chord fixed-step call (measured up to ~0.13 domain units apart on that same fixture). The linear-voice recipe presets (Menger/Sierpinski-membership style) are recipe-based and can never qualify for this path — only a genuine SDF voice (`menger`/`sierpinski`, `wave: "step"`) does. The two presets that originally exercised this — "Menger SDF"/"Sierpinski SDF" (one SDF voice each, carve, iter 3) — and the only other sphere-tracing-qualifying preset, "SDF bloom" (an animated variant of "Menger SDF"), were all three removed in a later preset cull (see "Preset named exports" above); no shipped preset currently exercises the SDF voice family or sphere tracing, though the mechanism remains fully implemented and tested. Measured speedup at the time: ~1.8-1.9× vs. fixed-step on the pinned half-covered 120×48 iter-3 scene (the design's drafted ≥2× floor assumed no stalls; the honest floor accounting for the fallback's own cost is lower, revised to ≥1.5×, which this cleared).

**Authoring tier: 9 voices, duty-aware Nyquist floor, program builder, program-as-data.** `SYNTH_VOICES` is 9 (bumped from 6); voices 7-9's key families are appended at the schema TAIL, never interleaved into the original `voice1..6` blocks — append-only ordering is load-bearing for the `/synth` URL codec's positional decode. The module-load schema guard now checks every one of the 14 per-voice key families (was 7 of 14), so a future voice bump can't ship with half its keys unchecked. The website imports `SYNTH_VOICES` directly instead of an independent `MAX_VOICES = 6` duplicate; voice Add caps at 9, layers stay 1..3. `voiceColorsAll`'s baked snapshot size changes with `SYNTH_VOICES` (re-pinned deliberately); render byte-identity holds regardless, since amp-0 voices are skipped in every fold and the exporter filters them the same way.

`effectiveVoiceFinestFreq` (the shared Nyquist step-count floor's per-voice input) is duty-aware for `square`-wave voices: `freq / min(duty, 1 − duty)` (two samples per narrowest band), replacing the old one-sample-per-band `2·freq` convention (at `duty = 0.5` the floor doubles — `freq → 2·freq` — a one-to-two-samples-per-band convention change, not an identity; no shipped preset's floor binds either way). `step` is non-periodic and unaffected; `sin`/`triangle`/`saw` keep plain `freq`. No shipped preset's floor changes (no shipped preset's finest voice bound the old formula); only patches with `chord · f_eff > marchSteps / 2` — the previously under-sampled class the fix targets — change. This makes the depth-3 Menger recipe safe: its finest band (1/27) now needs 94 steps, well inside the 256 cap (VOLUMETRIC-2.md's "depth-3 needs ≥~281 steps, out of v1's envelope" rationale used the un-fixed formula and was wrong by 3×, corrected here and in `bench/carve-march.md`). The depth-3 recipe no longer ships as its own preset (a later preset cull removed the standalone "Menger sponge" preset that used to carry it, though `GlyphCssGraphicsMengerPreset` still inlines the exact same recipe — see "Preset named exports" above); the gating remains as an EMPIRICAL hit-set-equality check against a 256-step ground-truth march on the acceptance scene, kept alive as a standalone params fixture in stock.test.ts — not formula trust, since no frequency bound can guarantee a thresholded multi-layer fold doesn't produce a wall thinner than its voices' nominal frequency implies.

`buildGlyphFieldProgram({ domain, layers: [{ combine?, threshold?, invert?, blend?, mix?, voices: [{ field, wave, freq, … }] }] })` (public, `@glyphcss/effects`) fills every IR default — including `sourceIndex`, numbered in flat authoring order, exactly mirroring field-synth's own flat-schema→IR compile — from the pleasant `voices: [...]` authoring surface; there is no `"inherit"` combine value (that's relative to a patch-level `combine` a hand-built program has no equivalent of), so `combine` defaults to `"multiply"` instead. `validateGlyphFieldProgram(program)` shape-validates an arbitrary value (layers/voices/origin fields/enum membership) before it reaches `evaluateFieldProgram`'s unguarded per-voice/per-layer dereferences, throwing a descriptive `TypeError` on the first structural problem rather than repairing or coercing.

**Program-as-data.** A `program?: unknown` option on `GlyphEffectDefinitionLayerOptions` (packages/glyphcss) carries an opaque, definition-owned program payload — glyphcss never imports or interprets it (the dependency points the other way: `@glyphcss/effects` depends on `glyphcss`, never the reverse) — forwarded unchanged onto `GlyphEffectEvaluateContext.program` and, when a definition supplies a `validateProgram(program)` hook (field-synth's own delegates to `validateGlyphFieldProgram`), validated once at MOUNT, not on every params transaction. Immutable after mount: the imperative handle's `setOptions` throws on a genuinely different `program` value (remove and re-add the layer to change it), mirroring mesh-handle `target`'s own immutable-after-mount rule; the React/Vue wrappers and `<glyph-effect-layer>` instead forward it ONLY at creation and silently no-op a later prop/config change, since neither diffs it on every render. When `program` is present, field-synth ignores its flat voice/layer params as the field definition (`params` still governs space/render/march/output mapping); `voiceColors` colors and the carve/xray finest-frequency both read from the PROGRAM's own voices, not the ignored flat params, and the `argmax` winner-color lookup is bounds-checked regardless of `sourceIndex` (previously a `sourceIndex ≥` palette length TypeErrored inside the render pass). `buildGlyphFieldSynthStaticExport` rejects a `program` option explicitly, before the flat-param merge/bake, through the same centralized reject gate `space: "object"`/carve/xray already use — an unbounded program-as-data payload has no schema this baked coordinate-table/affine-fit exporter can serialize. Not URL-persistable; the `/synth` page (API-tier only) never sets it.

`program`'s NAMED sibling is `colorProgram` (`GlyphEffectEvaluateContext.colorProgram`, `GlyphEffectDefinitionLayerOptions.colorProgram`): `program`'s opaque-payload contract has no room for a second independent program, so a definition driving two independent programs — field-synth's geometry stack plus its own independent colour voice stack — gets a second, separately named slot instead of overloading `program`. It mirrors `program` in every respect: opaque to glyphcss, forwarded unchanged, validated once at MOUNT via the definition's own `program.validateColorProgram` hook (field-synth's delegates to `validateGlyphFieldProgram`, same as `validateProgram`), and immutable after mount (`setOptions` throws on a genuinely different value; React/Vue and `<glyph-effect-layer>` forward it only at creation). Passed alongside `program`, not instead of it — geometry and colour are two separate programs when both are program-authored.
