# Diagrams: cell geometry, routing and fidelity

`@glyphcss/diagrams` implements Phase 2 over the public cell canvas. It depends on `glyphcss` and `@dagrejs/dagre`; it does not change the frozen canvas or existing 3D render path. The package is an asynchronous pure graph-to-text pipeline, and the workbench shares the real Instrument components used by charts and synth.

## Measurement owns node size

Labels are first folded through the canvas's grapheme policy, then wrapped at a cell width (default 18). ASCII applies its narrower repertoire after folding. `GLYPH_DIAGRAM_NODE_PAD` is one horizontal cell and zero extra vertical cells, plus borders. Every shape uses a rectangle for obstacle accounting; border cells distinguish the supported shapes without creating uncertain half-cell coverage.

Ports are reserved before dagre sees those rectangles. Both opposite sides reach their final size before either side gets centered offsets; otherwise a later wide outgoing fan leaves the incoming port off-center. A side with N attachments is enlarged to at least 2N + 1 cells, and attachment offsets differ by two cells. Horizontal-flow nodes grow vertically when their east/west sides need capacity. Every attachment owns its outward escape cell and approach lane; the router also protects the lane's one-cell neighbourhood. Reserving only the lane itself allowed a previous route to turn immediately beside a later edge's approach, making a visibly empty port unreachable. The LangGraph feedback route detects that defect.

## Stable layout and grouping

Nodes, edges, group ids and group members are sorted lexically by id, independent of locale. Missing edge ids are derived from endpoint/label/style/priority tuples and a stable duplicate index; they cannot collide with explicit ids. Measurement, reservation and layout do not mutate the input. Dagre sees measured dimensions, `nodesep` and `ranksep` in cells. Defaults are 4 / 4; both must be integers at least 3. The real 3.1.1 adapter uses `graphlib.Graph`, `setGraph({ rankdir, nodesep, ranksep, marginx, marginy })`, `setDefaultEdgeLabel`, and `layout(g)`. Node x/y are centres in the same cell units: subtract half the measured dimensions to locate the rectangle. Integer snapping is followed only by global translation, so node separation is never compressed to fit a viewport. Reserved port slots are assigned to edges in the opposite endpoints’ transverse coordinate order, with edge-id ties. Dagre 3 reverses some sibling orderings relative to the provisional engine; lexical slot assignment forced crossed fan-outs and made a planar diamond unroutable. Geometric slot assignment preserves the engine’s embedding without moving or resizing any node.

Nested or disjoint group membership becomes compound dagre parents. A global translation removes the engine's leading compound-caption whitespace while preserving distances. Partially overlapping membership sets cannot be represented as a tree; those groups are labelled by an explicit member list. Painting refuses an enclosure that would visually claim a nonmember. Group boundaries are annotation, not opaque node obstacles: they leave route cells visible.

The layout API returns a Promise even for dagre, leaving room for the future async ELK subpath. That subpath currently contains only the tagged stub. No ELK code or import enters the root bundle. The boundary test builds both ESM and CommonJS and imports them in a fresh Node process whose loaders reject any attempted elkjs resolution.

## Manhattan routing owns clearances

Each edge gets a separate polyline of all visited cells. A* state includes arrival direction, so the cost is length + 4 × bends + 12 × crossings. Caller cost overrides must be finite and nonnegative; a negative bend cost would reward cycles and invalidate termination. Bounds are positive integer cells. A binary heap and strict best-cost improvement make the search finite; no random tie-breaking or clock input occurs.

Node rectangles and their one-cell ring are obstacles. Only the current edge's endpoint escape cells can enter the ring. Other edges' reserved lanes and the neighbourhood of already routed parallel segments remain unavailable. A perpendicular crossing may use two straight transits; a corner/stub overlap cannot become a false junction. Crossing direction stays straight through the contested cell. Every result is checked for revisited cells because the frozen canvas cannot represent a repeated cell correctly.

When no route exists, an `unroutable` ledger entry names the edge and no transit is painted. This is not repaired by hiding a connector under a later box fill. The direct routing test puts a non-endpoint box on the shortest geometric path, then checks the actual detour. The six-port fixture checks dimensions, distinct ports, all six routes, and segment separation.

## Paint and labels

Every render creates a fresh canvas. Re-registering an edge on an old canvas cannot erase its prior drawing, so reuse would violate determinism. Routes are registered with their graph endpoint ids, resolved once, styled only on exclusive straight cells, then node borders are filled, target-border arrowheads replace their reserved border cells, and labels follow. Route polylines stop at the outside escape cell; the tip alone occupies the target border, never its label interior.

Three-row nodes have a one-cell vertical side. The frozen `line()` painter cannot infer a vertical orientation from coincident endpoints, so the diagrams painter writes that side using the tier's explicit vertical glyph. Node boxes are not routed as closed walks; that would exercise the canvas's repeated-cell limitation. Neither workaround edits the canvas.

External labels use `glyphDiagramLabelLayout` against node rectangles, every route cell and previously placed labels. Candidates are ordered by priority and id, measured in the same cell repertoire that paints them, abbreviated within the viewport, then placed at the nearest free rectangle. Edge-label candidates are restricted to rectangles immediately adjacent to their own route; if only distant space remains the label is dropped and reported, never floated elsewhere. Node labels use the same function inside their own reserved interior slot. The integration test reads actual label rectangles and final grid bytes, so a painter that forgets obstacles or overwrites labels fails, even if the standalone label helper remains correct.

Raw text, HTML and ANSI are independent exits. CSS supplies escaped HTML as well as plain text; ANSI modes supply SGR text. The explicit env option follows the canvas's nonempty NO_COLOR/FORCE_COLOR semantics. The page shows plain/CSS output, copies ANSI only through its dedicated action, and concatenates every split panel.

## Degradation and lineage

Budgets are 9 nodes and 12 edges. Excess count, dimensions or an unroutable connection invokes one bounded sequence: compaction → decoration → duplicate edges → sibling-leaf clusters → split. Each stage is logged. Original graph metadata survives every stage. `faithful` permits only compaction and splitting; `simplified` starts with decoration removal; `auto` and `balanced` share the Phase 2 budget. See "Round 3" below for the compaction rung and why it had to exist.

Splitting creates edge-induced panels, repeating boundary nodes and retaining isolated nodes as separate panels. Each has its own viewport and fresh canvas. The top-level text/HTML joins all panels with a blank line; top-level canvas/layout/routes remain the first panel, and `pages` provides each one explicitly. A viewport too small for endpoint boxes yields an explicitly reported blank panel, never partial boxes or clipped connections. This is a representational limit, not an unlabeled omission.

An intermediate failure inside a layout that FITS is logged as a routing attempt; a layout that doesn't fit at all is a `layout-overflow`, never a routing attempt misattributed to individual ports (Round 3). Final `report.unroutable` is derived only from final panels, so a successfully recovered connection is not still reported as missing.

### Ledger entries read like a sentence, not a log line

`report.ledger` is `GlyphDiagramLedgerEntry[]` — `{ code, message, detail? }`, mirroring `@glyphcss/charts`' own shape and rationale (its design note has the fuller argument for why a free-text `layout: ... 13 -> 7 (every 2th tick ...)`-style line reads as an internal log rather than something a reader was meant to see). `ledger.ts` is the one module every producer goes through: the five budget-ladder stages get their own stable `budget-compaction`/`budget-decoration`/`budget-duplicates`/`budget-leaf-clusters`/`budget-split` codes (deliberately NOT sharing the `budget-` prefix with `split-panel-dropped`, which is a per-panel outcome rather than a stage marker, so a caller can filter one from the other), duplicate/leaf-cluster degradation get `duplicate-edge-merged`/`leaf-cluster-collapsed`, group fallback gets `group-member-list`, label handling gets `label-abbreviated`/`label-dropped`/`label-folded`, routing gets `routing-attempt`/`unroutable`, and a plain size overflow gets its own `layout-overflow` (carrying the laid-out AND requested width/height, so a reader — or an agent parsing `detail` — can see by how much, not just that it happened; Round 3). A synthesized internal id (`glyphDiagramCollapseLeaves`'s own `cluster:[...]` cluster id, never user-authored) is kept out of the MESSAGE text specifically because its own colon would break the ledger's "no colon" sentence rule — it still rides in `detail`. The shared cell canvas's free-text double-diagonal note is parsed once at the paint boundary (`diagramLedgerEntryFromCanvasMessage`) into the same `double-diagonal-solid` shape `@glyphcss/charts` uses. `renderGlyphDiagram` dedupes its accumulated ledger by structural content (`dedupeGlyphDiagramLedger`, `JSON.stringify` equality) rather than `new Set` — a `Set` of entry OBJECTS never collapses two structurally-identical entries logged from separate `attempt()` passes, since each object literal is a distinct reference. The CLI prints each entry's `code`/`message` to stderr; the website's `/diagrams` page shows NO ledger readout — `report` is for the CLI and agents, not the page.

## Validation and source boundaries

Runtime validation and schema share rule ids and vocabularies. Graph references and uniqueness need cross-field comparisons unavailable in standard JSON Schema; the exported Ajv keyword supplies those exact relational checks. Ajv remains a dev dependency. Standalone schema users can apply structural validation, while consumers requiring complete parity register the keyword array.

Only Mermaid graph/flowchart grammars are accepted. Rejection identifies the declared unsupported diagram kind before trying to tokenize its foreign syntax. Quoted labels, `-. text .->` edge-text spans and `|label|` edge labels all protect statement separators the same way: a decoded HTML entity's own `;` (e.g. inside `&nbsp;`, which real `draw_mermaid()` output pads a conditional edge's text with) must never truncate a statement early. A quote can open INSIDE an edge-text or pipe span (`-->|"a|b"| B`, exactly what the workbench's own Mermaid exporter emits for a label containing `|`), so the quote check runs ahead of both spans rather than being shadowed by them. An edge-text span REQUIRES its `.->` terminator on the SAME statement: an unsupported dotted form (`-.-`, Mermaid's dotted-undirected link) that never finds one is a syntax error naming the statement, never a forward scan that swallows the next statement's own edge as this one's closing delimiter — the earlier defect turned a hard, actionable error into a silently WRONG graph (a deleted node, a fabricated edge with a garbled label). Label decoding is one left-to-right scan of the still-encoded text: an entity match always wins over Mermaid quote-escape interpretation at that position, and its decoded output is never re-scanned by a later pass. Two sequential whole-string passes (decode entities, then unescape `\"`/`\\`/`\'`) would instead treat a backslash *produced* by decoding `&#92;` as a second, spurious escape sequence and eat it — corrupting a round-tripped `\\server\share`-style label; quote-escapes are real Mermaid source syntax and only apply inside an actually-quoted label, never to an entity's decoded output. LangGraph's init directive and paragraph-wrapped stadium labels are accepted verbatim. `classDef`/`class`/`style`/`click`/`linkStyle` directives and `%%` comments are inert, never executable callbacks, network requests, or injected HTML. Bare references inside a subgraph count as members even when the nodes were declared earlier; this matters for JSON-to-Mermaid workbench round trips, whose generated group aliases now get the same collision avoidance as node aliases. Malformed input JSON is tagged `GLYPH_DIAGRAM_BAD_JSON` (via `parseGlyphDiagramJson`) at both `renderGlyphDiagramJson` and the compiled CLI's `.json` path, rather than surfacing a bare native `SyntaxError` with no `code`. `engine: "elk"` rejects with `GLYPH_DIAGRAM_ELK_NOT_INSTALLED` at `layoutGlyphGraph` itself — the same code the `./elk` stub throws — instead of a generic `bad-options`. Every id in `GLYPH_DIAGRAM_VALIDATION_RULES` carries its own dedicated repair hint, tested against the generic fallback string rather than mere truthiness.

## Round 3 (fan-out fix): a real LR fan-out couldn't render at all

`CHARTS-RESEARCH/DIAGNOSIS-diagrams-fanout.md` diagnosed why an 8-branch-shaped (6-node, 7-edge) LR fan-out/fan-in graph split into 7 panels at every requested size, and traced it to three root causes plus one misreported symptom, none of them regressions (byte-identical since the package's first commit).

**RC1/RC3 — `layoutGlyphGraph` never set dagre's `edgesep`.** dagre 3.1.1 defaults it to `20`, a bare pixel constant from its browser-diagram origin; `makeSpaceForEdgeLabels` inserts a dummy label-proxy node per edge into the intervening rank and spaces same-rank dummies `edgesep` apart, pulling their real sibling endpoints to the same pitch. In TB that pitch coincides with `nodesep` + label width (already ~20) and the defect is invisible; in LR the transverse axis is node HEIGHT (`3`), so three siblings cost 45 rows instead of ~19. `pipeline.ts`'s `setGraph` now passes `edgesep: 1` — the smallest legal separation on this integer cell grid, so there's no reason to spend more of the grid on it than its own unit. The same fix collapsed the 3-node fan-in case (RC3, previously forced into `leaf-clusters`, which replaces the fan with a `2 leaves` summary node — the only rung that could shrink an LR fan's HEIGHT before this). REVIEW-diagrams-fanout-opus.md P3-2b: `edgesep: 1` is NOT always identical in extent to `edgesep: nodesep` — true for the fan-out-lr graph alone (`80x19` either way); across the fixture corpus `1` is a row tighter than `nodesep` on `cycle` (`36x7` vs `36x8`) and on `langgraph`/`langgraph-export` in LR (`43x12` vs `43x13`). The substance holds (`1` is the smallest legal value and is never worse), only the "identical" claim was graph-specific.

**RC2 — the fit predicate had no compaction rung.** A 4-rank TB graph needs `4·3 + 3·4 + 2·1 = 26` rows at the default `nodesep`/`ranksep`/`margin` (`4`/`4`/`1`) — 2 over chat's 24, and none of the three semantic rungs (decoration, duplicates, leaf-clusters) can reduce a fan's HEIGHT without deleting it, so the graph fell straight to `split`. `render.ts`'s ladder now tries a `compaction` rung first: `margin: 0` (free — it only removes the engine's own leading whitespace), then a step-down search over `nodesep`/`ranksep` (see "Round 4" below for the current, per-graph floor and step-down search — the original single-constant-jump version is superseded). Compaction is non-semantic (spacing only, no content change) and so applies in every `detail` mode including `faithful`; once a candidate fits, its spacing sticks for every later attempt in the same render (decoration, duplicates, leaf-clusters, split can only benefit from the same tightening), and a candidate that doesn't help is discarded rather than left partially applied. A `budget-compaction` ledger entry logs only when it actually engages.

**RC4 — a size overflow was misreported as a routing failure.** `attempt()` always routes against the requested viewport, even when the raw layout doesn't fit it; every port landing outside the viewport used to log a per-edge `routing-attempt`, and the ledger never said which dimension overflowed by how much. `overflowOrRoutingAttempt` (`render.ts`) now checks `fits` first: a layout that doesn't fit logs one `layout-overflow` entry carrying the laid-out AND requested width/height; `routing-attempt` fires only for a genuine A* failure inside a layout that already fits.

**Why no fixture caught it.** No fixture had two LR siblings in one rank (the only configuration where `edgesep` is observable), every fixture render passed an explicit `width`/`height` that overrode chat's real `72x24` default to `80x32`, and no fixture had 4 ranks. `fixtures/fan-out-lr.mmd` (the O→{T,S,D}→M→R fan-out/fan-in, LR) and `fixtures/fan-2.mmd` (a 3-node fan) close the first two gaps, rendered through `{ target: "chat" }` with no size override; reading the SAME graph as `direction: "TB"` closes the third (4 ranks, needs exactly the compaction rung to fit chat height). All three render in one panel with every edge routed and no `routing-attempt` entry; an intentionally tiny viewport (`10x6`) still reaches `split` but reports `layout-overflow`, never `routing-attempt`, at both checkpoints. Fixing `edgesep` also moved five checked-in snapshots (`diamond`, `fan-out`, `cycle` box/ascii, `langgraph.chat60x20`) — every fixture whose ranks share a dummy chain with another edge (a fan or a back-edge) — to a tighter but structurally identical layout; `fixtureRules.test.ts`'s independent structural checks (all edges retained, no node/parallel-lane overlap, arrowheads on the target border, labels disjoint) passed on the new layouts unchanged, and `chain`/`subgraph` (no shared dummy chains) are byte-identical.

Mutation-checked: removing `edgesep: 1` reddens the fan-out-lr test (7 panels instead of 1, at both 72x24 and 96x32) — REVIEW-diagrams-fanout-opus.md P3-2a: `fan-2` does NOT red under this mutation at either size (its own layout simply fits at 96x32, and by "Round 4" below its compaction rung — now a per-graph floor and step-down search, not the original flat constant — rescues it at 72x24 regardless of `edgesep`), so `fan-2`'s test gates the compaction/RC2 fix jointly with `fan-out-lr`'s LR-fan-out shape rather than `edgesep` on its own; removing the compaction rung reddens the 4-rank TB test (falls through to `split`). Gates: diagrams 8 files / 194 tests, ESM/CJS/declarations build clean; website 117 files / 1554 tests, no snapshot changed by this fix (`/diagrams`' own tray presets don't include the new fixtures).

## Round 4 (fan-out fix review): the compaction rescue was undone downstream, its floor was a degree-3 measurement, and the overflow report wasn't retracted

`CHARTS-RESEARCH/REVIEW-diagrams-fanout-opus.md` reviewed Round 3 and found the `compaction` rung correct and a net win, but immediately undone by the very next rung, generalized from too small a sample, and unreachable at the library's own defaults.

**P1-1 — the `decoration` rung ran unconditionally, even after `compaction` already fixed the fit.** `render.ts`'s ladder guarded `duplicates` and `leaf-clusters` on `!current.okay`, but ran `decoration` whenever `opts.detail !== "faithful"`, full stop — so a diagram `compaction` alone already rescued (`diamond.mmd` at chat's own `{ target: "chat" }` default) still lost both its edge labels (`yes`/`no`) and its diamond shape to the very next rung, contradicting `budget-compaction`'s own ledger message ("before changing anything it draws"). Fixed with one added condition: decoration now runs only when `opts.detail === "simplified"` (which must keep dropping decoration by contract) or `!current.okay` (compaction didn't fully fix it). Gated by two tests: `diamond` at chat's real 72x24 keeps both labels and logs no `budget-decoration`, matching `detail: "faithful"`'s own label count exactly; `detail: "simplified"` still drops decoration even when compaction alone would have made the layout fit, preserving that mode's own contract. Mutation-checked: restoring the unconditional rung reddens both the dedicated test and the new chat-size snapshot loop (below) — `diamond`'s label count drops from 2 to 0.

**P2-1/P2-2 — the compaction floor was a degree-3 measurement stated as a universal constant, and unreachable at the library's own defaults.** The original `GLYPH_DIAGRAM_COMPACT_SPACING_FLOOR = 4` was derived from a 3-way fan (`ranksep: 3` fills the whole rank gap; `4` clears it) and asserted as the smallest spacing ANY fan can route at — false starting at degree 4 (`0/8` routed at spacing 4, needs `5`) and false again at degree 6 (`six-port.mmd` needs `7`). `glyphDiagramCompactionFloor(graph)` (`degrade.ts`) instead derives, per graph, `max(3, maxDegree + 1)` where `maxDegree` is the largest single-side port count (fan-in or fan-out) anywhere in the graph — the three measured points (degree 3 → floor 4, degree 4 → floor 5, degree 6 → floor 7) all land exactly on `N + 1`. It is a LOWER BOUND for a step-down search, not a promise that the floor itself routes every fan: `render.ts` now tries every integer spacing from the caller's own value down to that floor (never jumping straight to it, and no longer gated on the caller's spacing exceeding a flat constant — the old `nodesep > 4 || ranksep > 4` guard made the second candidate unreachable at the library's own `4`/`4` defaults, so compaction in practice was `margin: 0` alone for every default render), and accepts the FIRST candidate that both fits and routes every edge; a candidate that merely fits is kept only as a fallback in case none is fully routable. Gated by two tests: a degree-4 TB fan at `{ width: 44, height: 20, nodesep: 6, ranksep: 6 }` reaches the intermediate spacing-5 candidate the old constant-jump list skipped entirely (8 panels → 1, all 8 edges routed); `subgraph.mmd` read as TB at chat's real 72x24, at the library's own default spacing, reaches its own floor of 3 (max degree 1, clamped to the validated minimum) — unreachable under the old `> 4` guard — and renders whole (3 panels, 1 of 3 edges routed → 1 panel, 3 of 3). Mutation-checked: reverting to the flat constant-jump form reddens both.

**P2-3 — the pre-compaction `layout-overflow`/`routing-attempt` report was never retracted when compaction rescued the render.** `overflowOrRoutingAttempt` used to push before the compaction rung ran, so a diagram compaction then rendered whole still reported "too large… needs simplifying" right alongside `budget-compaction` — the CLI told its reader the diagram it had just finished rendering still needed simplifying. The push now happens AFTER compaction, using whatever `current` compaction left behind, so it reports nothing when compaction fully fixed the fit and routing. Gated by the existing "4-rank TB graph… via compaction" test, extended to assert `layout-overflow` is absent.

**P3-1 — a dotted route's dot/blank phase was keyed to its RAW cell index, which also counts undrawable corner cells.** `paint.ts`'s per-cell dot styling alternated on `i % 2` over `route.cells`' own index, but a corner cell (no straight `axis`) is skipped from styling while still consuming an index — so a short, corner-heavy route (`cycle.mmd`'s "retry" edge, 6 cells with 2 corners) could land its only two eligible cells on consecutive ODD indices and paint zero dots over its whole run, and a longer route (`langgraph.chat60x20`'s `agent -> __end__` dotted edge) had its phase silently shifted every time a corner intervened. Fixed with a per-route `dotPhase` counter that increments only on cells this loop actually draws, so the alternation is a clean dot-blank-dot-blank run regardless of how many corners sit between eligible cells; the route's two ENDPOINTS (the escape cell touching the source border, and the final cell touching the target's arrowhead) are now drawable too, since each has exactly one neighbour and a direction is well-defined from it alone — previously they kept whatever solid/corner glyph junction resolution produced, so a dotted edge's very first and last cells always looked solid regardless of style. Separately, `glyphDiagramLabelLayout` only rejected literal overlap, never adjacency, so a label candidate immediately touching a node's own border was never excluded — `cycle.mmd`'s short "retry" edge landed its label flush against the Check box (`└───────┘retry`) purely because its route geometry put the midpoint there, while every longer route's label happened to clear a node border by the geometry alone. `paint.ts` now pads NODE rects by one cell (never route point-obstacles, which a label is still required to touch at distance exactly 1) before handing them to the label layout, so every label keeps one cell of air from any box it isn't attached to. Both fixes re-derived three checked-in snapshots (`cycle.box.txt`, `cycle.ascii.txt`, `langgraph.chat60x20.txt`); no test asserted the OLD dot pattern or the missing gap (the loss was invisible to every existing structural check), so these are pure improvements caught only by re-reading the rendered picture.

**P3-3 — `layout-overflow` and `split-panel-dropped` used the same `width`/`height` keys for two different meanings.** `layout-overflow` put the LAID-OUT size there; `split-panel-dropped` put the REQUESTED viewport — an agent reading `detail` uniformly got opposite meanings from the same two keys depending which entry it landed on. `layout-overflow` now names its own addition `layoutWidth`/`layoutHeight`; both entries share `requestedWidth`/`requestedHeight` for the size actually asked for, so the same key means the same thing everywhere in the ledger. Gated by an extension of the existing size-overflow test, asserting both the new keys' presence and the old bare pair's absence on both entry types.

**P3-4 — no CHECKED-IN snapshot rendered at chat's own real default size.** The existing snapshot loop and `fixtureRules.test.ts`'s contract loop both pass `width: 80, height: 32`, overriding `GLYPH_DIAGRAM_TARGET_DEFAULTS.chat`'s real `72x24` — exactly the size P1-1's regression hid at. A second snapshot loop now renders the same five fixtures at `{ target: "chat" }` with no size override, so a future change to the target defaults moves it too; at 80x32 every one of the five fixtures renders with an EMPTY ledger (no degrade rung ever engages there, since there's headroom to spare), which is a genuinely distinct, still-useful baseline-layout check, so it stays alongside the new loop rather than being replaced by it.

**P3-5 — `GLYPH_DIAGRAM_DEGRADE_STAGES` had no consumer.** `ledger.ts`'s `ledgerBudgetStage` used to repeat the five stage names as its own separately-typed literal union; it now derives its parameter type from `GLYPH_DIAGRAM_DEGRADE_STAGES` (a type-only import, so no runtime circular dependency between the two modules that already import from each other), so the two can never drift apart.

Gates: `pnpm --filter @glyphcss/diagrams test` (typecheck + vitest) and `pnpm --filter @glyphcss/diagrams build` (ESM/CJS/DTS); `pnpm --filter @glyphcss/website test` for the shared `/diagrams` page and workbench state.

## D5 — Hugging Face graph dataset search, and why molecules default to 3D layered

The user's own request: mirror `/charts`' Hugging Face dataset search, but for graphs. `website/src/lib/graphDatasetLoad.ts` (loader), `website/src/lib/graphDatasetSearch.ts` (live search), `website/src/components/DiagramsWorkbench/datasets/remoteGraphIndex.ts` (curated index), `DiagramsDatasetSearchBox.tsx`/`DiagramsDataOverlay.tsx`/`DiagramsGraphSourceCard.tsx` (UI), and `diagramsRandomGraph.ts` (Random's own combined pool).

**Verified data source, live, 2026-09-15.** The Hugging Face `graphs-datasets` org serves one graph per ROW through the public, unauthenticated `datasets-server.huggingface.co` `/splits` + `/rows` service: `edge_index: [[src...],[dst...]]`, `num_nodes`, optional `node_feat`/`edge_attr`, and a graph label `y`. Confirmed by direct HTTP round trips (not assumed from the brief) against MUTAG, ZINC, AIDS, twitch_egos, deezer_ego_nets, reddit_threads and IMDB-BINARY — split names genuinely differ per dataset (`train`, `full`, `train`/`test`/`validation`), so the loader resolves `/splits` fresh per ref rather than assuming a name. An undirected relationship is stored as BOTH `(a,b)` and `(b,a)` — verified on MUTAG's own row 0 (17 nodes, 38 directed columns, exactly 19 survive the dedupe) — `graphDatasetRowToGraph` collapses a mirror pair to one `GlyphGraphEdge` and reports the count removed.

**Node labelling — the brief's own claim didn't hold up.** The brief states MUTAG's one-hot order is "confirm the order from the card" and that "ZINC's atom-type vocabulary is on its card." Read live: NEITHER card documents an atom order at all — both show only feature shapes/dtypes. MUTAG's card does say its graphs come from "the PyGeometric version of the dataset provided by OGB," which is the canonical TU Dortmund 7-way order (C, N, O, F, I, Cl, Br) every GNN benchmark suite agrees on, so it's kept — on that external anchor, not the card. ZINC has no such anchor on its own card (its `node_feat` is a single integer atom CODE, not a one-hot vector, and the well-known 28-way ZINC vocabulary from the "Benchmarking GNNs" paper is a DIFFERENT external source with no card-stated confirmation) — guessing it wrong would silently mislabel every atom, so ZINC (and every other curated dataset) falls back to its bare node index instead.

**Curated index (7 datasets, `remoteGraphIndex.ts`), each verified live via `/splits`+`/rows`, with title/description/licence read off its own card:**

| Dataset | Kind | #graphs | avg nodes | licence (as stated) |

| MUTAG | molecule | 187 | 18.0 | unknown |
| ZINC | molecule | 220,011 (train) | 23.2 | unknown |
| AIDS | molecule | ~1,999 | 15.6 | not stated (no `license` key on the card at all) |

AIDS's absent `license` key is recorded as `"not stated"`, kept distinct from MUTAG/ZINC/IMDB-BINARY's own literal `"unknown"` string — the two are different facts (no field at all vs. a card that explicitly says it doesn't know) and collapsing them would misreport the AIDS card.

**Size budget.** `GRAPH_DATASET_NODE_CAP = 40` — sized off a real render, not a guess: `renderGlyphDiagram` on a genuine 13-node/14-edge MUTAG row already blows the 2D engine's `split` fallback into a wall of one-edge-per-page fragments (the 2D budget, AGENTS.md's own "Diagrams," is 9 nodes/12 edges before any degrade rung even engages), so 40 nodes stays comfortably inside every curated molecule's own average while still forcing `deezer_ego_nets`' much larger ego-nets (avg 287) into a labelled truncation. `loadGraphDatasetRow(ref, rowIdx)` truncates and reports `simplified: true` unconditionally when asked for a specific oversized row (a `?d=` link or a search-box "Load X" pick must resolve to THAT row); `loadRandomGraphDatasetRow` instead retries up to 5 different row indices before accepting a truncation, so Random on a dataset with plenty of small graphs (MUTAG, AIDS, IMDB-BINARY) essentially never simplifies in practice, and only falls back to a truncated pick on a dataset like `deezer_ego_nets` whose typical graph already exceeds the cap.

**Molecules default to the 3D LAYERED view — decided by rendering, not by the brief's own hedge ("with the force layout if it reads better").** A throwaway `vitest` render (`packages/diagrams/src/scratch-graph-render.test.ts`, deleted after use) compared real MUTAG row-1 (13 nodes) and ZINC row-1 (18 nodes) through `renderGlyphDiagram` (2D), `renderGlyphDiagram3d({ layout: "layered" })` and `renderGlyphDiagram3d({ layout: "force" })` at 100×40 braille. Findings: 2D fragments into the `split` wall described above even at 13 nodes — illegible. 3D LAYERED draws each molecule as one clean diagonal chain, atom labels legible at every node, edges unambiguous. 3D FORCE tangles the SAME small molecule into a dense, overlapping mess with crossing strands — worse than layered, not better, because a molecule's low-degree near-linear/ring topology is exactly the shape a rank-based layered embedding suits and a general-purpose force layout does not. `select-remote-graph`'s reducer therefore sets `view: "3d"`, `view3d.layout: "layered"` when `DIAGRAMS_MOLECULE_GRAPH_REFS.has(ref)` (MUTAG/ZINC/AIDS); every other curated dataset (the ego-nets, threads, collaboration graph) stays on the ordinary 2D default, which the size cap already keeps legible for their own typical graph size.

**URL state — the graph itself is never stored for a remote pick.** `graphSource: GlyphDiagramsGraphSource` (`diagramsWorkbenchState.ts`) is `{ kind: "builtin", presetId }` or `{ kind: "remote", ref, rowIdx, totalRows, title, description?, label?, simplified?, source, omitted? }`, both APPEND-ONLY optional fields on the workbench state — an old link decodes with `graphSource`/`graphEdited` genuinely absent, never backfilled to today's default (pinned in `diagramsUrlState.test.ts`'s own historical-link regression test, updated to state the one field it now legitimately diverges on). `diagramsUrlStateForEncode` (mirroring `chartsUrlState.ts`'s own `chartsUrlStateForEncode`/`dataOmitted`) blanks `nodes`/`edges`/`mermaid`/`json` and stamps `graphSource.omitted: true` whenever the loaded graph is a REMOTE pick the reader has NOT since edited (`state.graphEdited`, set by any Mermaid/JSON/table edit action, reset on every fresh load); an EDITED remote graph rides in the link in full, since there is no local copy to silently discard real work against. `DiagramsWorkbench.tsx`'s mount effect re-fetches `ref`/`rowIdx` fresh and dispatches `select-remote-graph` exactly when `graphSource.omitted` is set, mirroring `ChartsWorkbench.tsx`'s own `initialRemoteRef` split.

**View molecules default to, and why:** 3D, layered layout (not force) — see above. Every other curated dataset defaults to 2D.

**Residuals.** No `glyphGraphFromEdgeIndex` library export was added — the HF-specific fetch/dedupe/cap/label logic has no reuse outside this one page, so it stays in `website/src/lib/graphDatasetLoad.ts` per the task's own "if you add it, keep it tiny" allowance read as optional. Reopening a shared `?d=` link for an UN-edited remote graph re-derives `view`/`view3d`/`camera3d` from `select-remote-graph`'s own molecule-preference logic exactly like a fresh pick would (mirrors `/charts`' own remote-dataset reducer, which resets scales/axes the same way) — a camera or view override made on such a link is not itself preserved, only the ref/rowIdx/title snapshot is; an EDITED graph's full state (view included) rides in full. `edge_attr` is read off every row but not surfaced anywhere (`GlyphGraphEdge` has no numeric-feature slot, only `label`/`style`) — a future packet wanting edge weights/bond types would need a library-side field addition first.
