# Diagrams: cell geometry, routing and fidelity

`@glyphcss/diagrams` implements Phase 2 over the public cell canvas. It depends on `glyphcss` and `@dagrejs/dagre`; it does not change the frozen canvas or existing 3D render path. The package is an asynchronous pure graph-to-text pipeline, and the workbench shares the real Instrument components used by charts and synth.

## Measurement owns node size

Labels are first folded through the canvas's grapheme policy, then wrapped at a cell width (default 18). ASCII applies its narrower repertoire after folding. `GLYPH_DIAGRAM_NODE_PAD` is one horizontal cell and zero extra vertical cells, plus borders. Every shape uses a rectangle for obstacle accounting; border cells distinguish the supported shapes without creating uncertain half-cell coverage.

Ports are reserved before dagre sees those rectangles. Both opposite sides reach their final size before either side gets centered offsets; otherwise a later wide outgoing fan leaves the incoming port off-center. A side with N attachments is enlarged to at least 2N + 1 cells, and attachment offsets differ by two cells. Horizontal-flow nodes grow vertically when their east/west sides need capacity. Every attachment owns its outward escape cell and approach lane; the router also protects the lane's one-cell neighbourhood. Reserving only the lane itself allowed a previous route to turn immediately beside a later edge's approach, making a visibly empty port unreachable. The LangGraph feedback route detects that defect.

## Stable layout and grouping

Nodes, edges, group ids and group members are sorted lexically by id, independent of locale. Missing edge ids are derived from endpoint/label/style/priority tuples and a stable duplicate index; they cannot collide with explicit ids. Measurement, reservation and layout do not mutate the input. Dagre sees measured dimensions, `nodesep` and `ranksep` in cells. Defaults are 4 / 4; both must be integers at least 3. The real 3.1.1 adapter uses `graphlib.Graph`, `setGraph({ rankdir, nodesep, ranksep, marginx, marginy })`, `setDefaultEdgeLabel`, and `layout(g)`. Node x/y are centres in the same cell units: subtract half the measured dimensions to locate the rectangle. Integer snapping is followed only by global translation, so node separation is never compressed to fit a viewport. Reserved port slots are assigned to edges in the opposite endpoints’ transverse coordinate order, with edge-id ties. Dagre 3 reverses some sibling orderings relative to the provisional engine; lexical slot assignment forced crossed fan-outs and made a planar diamond unroutable. Geometric slot assignment preserves the engine’s embedding without moving or resizing any node.

Nested or disjoint group membership becomes compound dagre parents. A global translation removes the engine's leading compound-caption whitespace while preserving distances. Partially overlapping membership sets cannot be represented as a tree; those groups are labelled by an explicit member list. Painting refuses an enclosure that would visually claim a nonmember. Group boundaries are annotation, not opaque node obstacles: they leave route cells visible.

The layout API returns a Promise even for dagre, leaving room for the future async ELK subpath. That subpath currently contains only the tagged stub. No ELK code or import enters the root bundle. The boundary test builds both ESM and CommonJS and imports them in a fresh Node process whose loaders reject any attempted elkjs resolution.

## Manhattan routing owns clearances

Each edge gets a separate polyline of all visited cells. A* state includes arrival direction, so the cost is length + 4 × bends + 12 × crossings. Caller cost overrides must be finite and nonnegative; a negative bend cost would reward cycles and invalidate termination. Bounds are positive integer cells. A binary heap and strict best-cost improvement make the search finite; no random tie-breaking or clock input occurs.

Node rectangles and their one-cell ring are obstacles. Only the current edge's endpoint escape cells can enter the ring. Other edges' reserved lanes and the neighbourhood of already routed parallel segments remain unavailable. A perpendicular crossing may use two straight transits; a corner/stub overlap cannot become a false junction. Crossing direction stays straight through the contested cell. Every result is checked for revisited cells because the frozen canvas cannot represent a repeated cell correctly.

When no route exists, an `unroutable` ledger entry names the edge and no transit is painted. This is not repaired by hiding a connector under a later box fill. The direct routing test puts a non-endpoint box on the shortest geometric path, then checks the actual detour. The six-port fixture checks dimensions, distinct ports, all six routes, and segment separation.

## Paint and labels

Every render creates a fresh canvas. Re-registering an edge on an old canvas cannot erase its prior drawing, so reuse would violate determinism. Routes are registered with their graph endpoint ids, resolved once, styled only on exclusive straight cells, then node borders are filled, target-border arrowheads replace their reserved border cells, and labels follow. Route polylines stop at the outside escape cell; the tip alone occupies the target border, never its label interior.

Three-row nodes have a one-cell vertical side. The frozen `line()` painter cannot infer a vertical orientation from coincident endpoints, so the diagrams painter writes that side using the tier's explicit vertical glyph. Node boxes are not routed as closed walks; that would exercise the canvas's repeated-cell limitation. Neither workaround edits the canvas.

External labels use `glyphDiagramLabelLayout` against node rectangles, every route cell and previously placed labels. Candidates are ordered by priority and id, measured in the same cell repertoire that paints them, abbreviated within the viewport, then placed at the nearest free rectangle. Edge-label candidates are restricted to rectangles immediately adjacent to their own route; if only distant space remains the label is dropped and reported, never floated elsewhere. Node labels use the same function inside their own reserved interior slot. The integration test reads actual label rectangles and final grid bytes, so a painter that forgets obstacles or overwrites labels fails, even if the standalone label helper remains correct.

Raw text, HTML and ANSI are independent exits. CSS supplies escaped HTML as well as plain text; ANSI modes supply SGR text. The explicit env option follows the canvas's nonempty NO_COLOR/FORCE_COLOR semantics. The page shows plain/CSS output, copies ANSI only through its dedicated action, and concatenates every split panel.

## Degradation and lineage

Budgets are 9 nodes and 12 edges. Excess count, dimensions or an unroutable connection invokes one bounded sequence: compaction → decoration → duplicate edges → sibling-leaf clusters → split. Each stage is logged. Original graph metadata survives every stage. `faithful` permits only compaction and splitting; `simplified` starts with decoration removal; `auto` and `balanced` share the Phase 2 budget. See "Round 3" below for the compaction rung and why it had to exist.

Splitting creates edge-induced panels, repeating boundary nodes and retaining isolated nodes as separate panels. Each has its own viewport and fresh canvas. The top-level text/HTML joins all panels with a blank line; top-level grid/layout/routes remain the first panel, and `pages` provides each one explicitly. A viewport too small for endpoint boxes yields an explicitly reported blank panel, never partial boxes or clipped connections. This is a representational limit, not an unlabeled omission.

An intermediate failure inside a layout that FITS is logged as a routing attempt; a layout that doesn't fit at all is a `layout-overflow`, never a routing attempt misattributed to individual ports (Round 3). Final `report.unroutable` is derived only from final panels, so a successfully recovered connection is not still reported as missing.

### Ledger entries read like a sentence, not a log line

`report.ledger` is `GlyphDiagramLedgerEntry[]` — `{ code, message, detail? }`, mirroring `@glyphcss/charts`' own shape and rationale (its design note has the fuller argument for why a free-text `layout: ... 13 -> 7 (every 2th tick ...)`-style line reads as an internal log rather than something a reader was meant to see). `ledger.ts` is the one module every producer goes through: the five budget-ladder stages get their own stable `budget-compaction`/`budget-decoration`/`budget-duplicates`/`budget-leaf-clusters`/`budget-split` codes (deliberately NOT sharing the `budget-` prefix with `split-panel-dropped`, which is a per-panel outcome rather than a stage marker, so a caller can filter one from the other), duplicate/leaf-cluster degradation get `duplicate-edge-merged`/`leaf-cluster-collapsed`, group fallback gets `group-member-list`, label handling gets `label-abbreviated`/`label-dropped`/`label-folded`, routing gets `routing-attempt`/`unroutable`, and a plain size overflow gets its own `layout-overflow` (carrying the laid-out AND requested width/height, so a reader — or an agent parsing `detail` — can see by how much, not just that it happened; Round 3). A synthesized internal id (`glyphDiagramCollapseLeaves`'s own `cluster:[...]` cluster id, never user-authored) is kept out of the MESSAGE text specifically because its own colon would break the ledger's "no colon" sentence rule — it still rides in `detail`. The shared cell canvas's free-text double-diagonal note is parsed once at the paint boundary (`diagramLedgerEntryFromCanvasMessage`) into the same `double-diagonal-solid` shape `@glyphcss/charts` uses. `renderGlyphDiagram` dedupes its accumulated ledger by structural content (`dedupeGlyphDiagramLedger`, `JSON.stringify` equality) rather than `new Set` — a `Set` of entry OBJECTS never collapses two structurally-identical entries logged from separate `attempt()` passes, since each object literal is a distinct reference. The CLI prints each entry's `code`/`message` to stderr; the website's `/diagrams` page shows NO ledger readout — `report` is for the CLI and agents, not the page.

## Validation and source boundaries

Runtime validation and schema share rule ids and vocabularies. Graph references and uniqueness need cross-field comparisons unavailable in standard JSON Schema; the exported Ajv keyword supplies those exact relational checks. Ajv remains a dev dependency. Standalone schema users can apply structural validation, while consumers requiring complete parity register the keyword array.

Only Mermaid graph/flowchart grammars are accepted. Rejection identifies the declared unsupported diagram kind before trying to tokenize its foreign syntax. Quoted labels, `-. text .->` edge-text spans and `|label|` edge labels all protect statement separators the same way: a decoded HTML entity's own `;` (e.g. inside `&nbsp;`, which real `draw_mermaid()` output pads a conditional edge's text with) must never truncate a statement early. A quote can open INSIDE an edge-text or pipe span (`-->|"a|b"| B`, exactly what the workbench's own Mermaid exporter emits for a label containing `|`), so the quote check runs ahead of both spans rather than being shadowed by them. An edge-text span REQUIRES its `.->` terminator on the SAME statement: an unsupported dotted form (`-.-`, Mermaid's dotted-undirected link) that never finds one is a syntax error naming the statement, never a forward scan that swallows the next statement's own edge as this one's closing delimiter — the earlier defect turned a hard, actionable error into a silently WRONG graph (a deleted node, a fabricated edge with a garbled label). Label decoding is one left-to-right scan of the still-encoded text: an entity match always wins over Mermaid quote-escape interpretation at that position, and its decoded output is never re-scanned by a later pass. Two sequential whole-string passes (decode entities, then unescape `\"`/`\\`/`\'`) would instead treat a backslash *produced* by decoding `&#92;` as a second, spurious escape sequence and eat it — corrupting a round-tripped `\\server\share`-style label; quote-escapes are real Mermaid source syntax and only apply inside an actually-quoted label, never to an entity's decoded output. LangGraph's init directive and paragraph-wrapped stadium labels are accepted verbatim. `classDef`/`class`/`style`/`click`/`linkStyle` directives and `%%` comments are inert, never executable callbacks, network requests, or injected HTML. Bare references inside a subgraph count as members even when the nodes were declared earlier; this matters for JSON-to-Mermaid workbench round trips, whose generated group aliases now get the same collision avoidance as node aliases. Malformed input JSON is tagged `GLYPH_DIAGRAM_BAD_JSON` (via `parseGlyphDiagramJson`) at both `renderGlyphDiagramJson` and the compiled CLI's `.json` path, rather than surfacing a bare native `SyntaxError` with no `code`. `engine: "elk"` rejects with `GLYPH_DIAGRAM_ELK_NOT_INSTALLED` at `layoutGlyphGraph` itself — the same code the `./elk` stub throws — instead of a generic `bad-options`. Every id in `GLYPH_DIAGRAM_VALIDATION_RULES` carries its own dedicated repair hint, tested against the generic fallback string rather than mere truthiness.

## Round 2 (final-gate-2): the table dropped graph-level fields, and the bare API defaulted to chat

`CHARTS-RESEARCH/REVIEW-final2-*.md` (`34894153..f8137df5`).

**Switching to the Table tab and editing one cell dropped `groups` and reset `direction`.** `buildGlyphDiagramsWorkbenchGraph`'s table branch rebuilt the graph as `{ nodes: state.nodes, edges: state.edges, direction: state.layout.direction ?? "TB" }` — the workbench state tracked `nodes`/`edges` for the table view but nothing for the graph-level fields the table doesn't expose. Applying the Subgraph or CrewAI-style crew preset (both grouped, one `LR`), switching to Table, and editing a single node's label replaced the entire render with an `unknown-group` validation error (the rebuilt graph declared no groups at all, so a node's own `group` field named one that didn't exist) and silently reset `LR` to `TB`. Fixed by carrying a `tableGraph: { groups?, direction }` sidecar on workbench state, populated everywhere `nodes`/`edges` are set from a freshly parsed graph (initial state, `apply-preset`, switching INTO the table) and left untouched by every table-only edit (`set-node`, `add-edge`, ...) — exactly the same verbatim-preservation rule the table's own node-level `group`/`shape` fields already followed, just missing at the graph level. `?d=` links gained the matching `tableGraph` field, appended per the envelope's own append-only rule (an old link without it decodes to `{ direction: "TB" }`, the exact default the pre-fix code always built anyway).

**`renderGlyphDiagram`/`renderGlyphDiagramJson` defaulted to `target: "chat"` with no options**, while `renderGlyphChart` had already moved its own bare-call default to `"web"`. AGENTS.md's "Targets/options mirror charts" was documentation for a mirror that didn't yet exist in code. Now `options.target ?? "web"`, matching charts exactly; a bare call returns 96x32 braille/CSS with `html` populated, not 72x24 box/no-HTML.

## Round 3 (fan-out fix): a real LR fan-out couldn't render at all

`CHARTS-RESEARCH/DIAGNOSIS-diagrams-fanout.md` diagnosed why an 8-branch-shaped (6-node, 7-edge) LR fan-out/fan-in graph split into 7 panels at every requested size, and traced it to three root causes plus one misreported symptom, none of them regressions (byte-identical since the package's first commit).

**RC1/RC3 — `layoutGlyphGraph` never set dagre's `edgesep`.** dagre 3.1.1 defaults it to `20`, a bare pixel constant from its browser-diagram origin; `makeSpaceForEdgeLabels` inserts a dummy label-proxy node per edge into the intervening rank and spaces same-rank dummies `edgesep` apart, pulling their real sibling endpoints to the same pitch. In TB that pitch coincides with `nodesep` + label width (already ~20) and the defect is invisible; in LR the transverse axis is node HEIGHT (`3`), so three siblings cost 45 rows instead of ~19. `pipeline.ts`'s `setGraph` now passes `edgesep: 1` — the smallest legal separation on this integer cell grid, measured identical in resulting extent to `edgesep: nodesep` (`80x19` either way) once it's off the pixel default, so there's no reason to spend more of the grid on it than its own unit. The same fix collapsed the 3-node fan-in case (RC3, previously forced into `leaf-clusters`, which replaces the fan with a `2 leaves` summary node — the only rung that could shrink an LR fan's HEIGHT before this).

**RC2 — the fit predicate had no compaction rung.** A 4-rank TB graph needs `4·3 + 3·4 + 2·1 = 26` rows at the default `nodesep`/`ranksep`/`margin` (`4`/`4`/`1`) — 2 over chat's 24, and none of the three semantic rungs (decoration, duplicates, leaf-clusters) can reduce a fan's HEIGHT without deleting it, so the graph fell straight to `split`. `render.ts`'s ladder now tries a `compaction` rung first: `margin: 0` (free — it only removes the engine's own leading whitespace), then, if that's not enough, the smallest `nodesep`/`ranksep` the port-lane reservation still tolerates. That floor is `GLYPH_DIAGRAM_COMPACT_SPACING_FLOOR = 4`, derived from `route.ts`'s own reservation rule: each port protects its escape cell plus one more cell further out (`otherLanes`), and at `ranksep: 3` those two protected lanes — one from each side of the gap — fill every row between the node borders, leaving no free row for another edge's transverse jog; measured directly, `ranksep: 3` left a real fan-in's `S->M`/`T->M` edges unroutable while `4` routed them cleanly. Compaction is non-semantic (spacing only, no content change) and so applies in every `detail` mode including `faithful`; once a candidate fits, its spacing sticks for every later attempt in the same render (decoration, duplicates, leaf-clusters, split can only benefit from the same tightening), and a candidate that doesn't help is discarded rather than left partially applied. A `budget-compaction` ledger entry logs only when it actually engages.

**RC4 — a size overflow was misreported as a routing failure.** `attempt()` always routes against the requested viewport, even when the raw layout doesn't fit it; every port landing outside the viewport used to log a per-edge `routing-attempt`, and the ledger never said which dimension overflowed by how much. `overflowOrRoutingAttempt` (`render.ts`) now checks `fits` first: a layout that doesn't fit logs one `layout-overflow` entry carrying the laid-out AND requested width/height; `routing-attempt` fires only for a genuine A* failure inside a layout that already fits.

**Why no fixture caught it.** No fixture had two LR siblings in one rank (the only configuration where `edgesep` is observable), every fixture render passed an explicit `width`/`height` that overrode chat's real `72x24` default to `80x32`, and no fixture had 4 ranks. `fixtures/fan-out-lr.mmd` (the O→{T,S,D}→M→R fan-out/fan-in, LR) and `fixtures/fan-2.mmd` (a 3-node fan) close the first two gaps, rendered through `{ target: "chat" }` with no size override; reading the SAME graph as `direction: "TB"` closes the third (4 ranks, needs exactly the compaction rung to fit chat height). All three render in one panel with every edge routed and no `routing-attempt` entry; an intentionally tiny viewport (`10x6`) still reaches `split` but reports `layout-overflow`, never `routing-attempt`, at both checkpoints. Fixing `edgesep` also moved five checked-in snapshots (`diamond`, `fan-out`, `cycle` box/ascii, `langgraph.chat60x20`) — every fixture whose ranks share a dummy chain with another edge (a fan or a back-edge) — to a tighter but structurally identical layout; `fixtureRules.test.ts`'s independent structural checks (all edges retained, no node/parallel-lane overlap, arrowheads on the target border, labels disjoint) passed on the new layouts unchanged, and `chain`/`subgraph` (no shared dummy chains) are byte-identical.

Mutation-checked: removing `edgesep: 1` reddens the fan-out-lr/fan-2 test (7 panels instead of 1, at both 72x24 and 96x32); removing the compaction rung reddens the 4-rank TB test (falls through to `split`). Gates: diagrams 8 files / 194 tests, ESM/CJS/declarations build clean; website 117 files / 1554 tests, no snapshot changed by this fix (`/diagrams`' own tray presets don't include the new fixtures).
